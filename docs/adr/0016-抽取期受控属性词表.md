# ADR-0016 抽取期直出受控 attribute（canonical 属性词表）

- 状态：提议（2026-10-30，#167 实施已落地，但 §23 的 single-only 读数未证实收益；生产开关仍随 `memory.write.factRows.enabled` 缺省关，开启前须补 §23.6 配对读数）。
- 关联：#146 / ADR-0015（事实级双时态与 factKey 契约）、#136 / ADR-0010（属性基数契约）、docs/optimization-results.md §22（谓词归一 0.0% 收益）、§23（本决定的配对读数）。
- 落点：`MemoryCore/src/core/record/fact-attribute.ts`（词表/归一/基数裁决单一源）、`fact-key.ts`（三元组承载 attribute）、`fact-row.ts`、`supersession.ts`（`factKeyOf`）、`core/prompts/l1-extraction.ts`、`scripts/lib/bench/facts.mjs`、`scripts/audit/r167-attribute-*.mjs`。

## 背景

#146 的事实键是 `(normSubject, normPredicate)`。谓词是抽取器自由文本（`lives in` / `moved to` / `is considering` / `plans to`），同一语义属性每次措辞不同，键永不相等。真实语料上谓词同义族归一**零收益**（1796 三元组、1461 个不同键，归一并列前后完全相同，§22.6），结论是把「属性」提升为抽取期直出的受控字段，而不是继续在写侧猜谓词同义。

## 决定

1. **封闭词表，单一源**：`FACT_ATTRIBUTES` 24 项（single 10 / multi 14），每项 `{name, cardinality, description}`。提示词、bench 抽取、归一、测试与 metrics 都引用这一份；名字是 snake_case canonical 名，描述进提示词让模型按语义挑而不是按名字猜。词表是人工归纳（依据 §22 的 1796 三元组属性分布与 KU 切片复核），不是运行时自动聚类——自动聚类无法保证跨轮稳定，而键必须稳定。
2. **attribute 优先决定事实键**：`factKeyOf(subject, predicate, attribute)` 在 attribute 表内时返回 `normSubject + "\u0000" + "@attr:" + attribute`；无 attribute（或表外脏值）逐位回落 #146 的 `(normSubject, normPredicate)`。`@attr:` 前缀让属性槽与谓词槽不会因字面同名误撞；旧数据不重写、不迁移。
3. **基数裁决单一阶梯**：`resolveFactCardinality(attribute, explicit, fallback)` = **attribute > 显式 cardinality > fallback（含 `cardinalityDefault` 与谓词启发式）**。理由：attribute 来自封闭词表，档位即语义（`residence` 天然 single）；显式值是自由文本，只应在无 attribute 时补充。写侧 `fact-row` 与读侧 `supersession` 共用该函数，禁止各写一套优先级。
4. **别名只做同义词/词形容错**：只收 `job`、`hobbies`、`plans`、`email_address` 这类同义或词形变体。`title`（书名与职位同形）、`city` / `location`（分不清常住地与旅行目的地）、`relationship_status`（与 multi 的 `relationship` 重叠）故意不收；错并会把多值误判成 single，比漏标更贵。表外/歧义词一律 undefined，写侧回落谓词路径。
5. **可观测性不另设专键**：attribute 随 `metadata.factTriples[0].attribute` 落库（与 subject/predicate 同一载体），不新增 `fact_attribute` metadata 键——没有读侧消费者，专键只是重复状态。
6. **迁移与开关**：只有新抽取（facts-v4 及以后）会带 attribute；已落库的谓词键旧行不会被新 attribute 键失效（无 backfill、无重写）。生产 `factRows` 缺省关，本决定不改变该开关；开启前必须完成 §23 的质量与配对读数。
7. **测量口径**：同时报三种同键跨轮重复率——①全局池化（对齐 §22.3 旧口径，跨 case 混键）；②题内 per-case 全部行（衡量键收敛）；③题内 per-case **仅解析后 single 行**（真正的失效触发面，multi 按设计永不失效）。只报全部行的题内率会拿永不失效的 multi 键冒充收益；只报池化率会被跨 case 混键污染。§23 已按这三把尺子重写，结论是 single-only 口径下收益假设不成立。

## 理由

- **键必须在抽取期稳定**：写侧同义表只能覆盖已知词形，真实语料的谓词长尾不可枚举；封闭 attribute 把「同义」判定前移到模型，一次抽取、读写共用。
- **封闭优于开放**：开放 attribute 会退化成第二个自由文本谓词；词表外一律回落谓词键，保证坏值不放大。
- **基数与属性同源**：属性语义本身决定能否并存（常住地 vs 兴趣），让词表压过抽取器随手写的 cardinality，避免「residence + multi」这类自相矛盾。

## 后果

- **收益面**：attribute 让不同谓词的同一属性撞键，事实级失效从「谓词字面相同」扩展到「属性相同」；单值属性（residence/occupation/employer/education/age/phone/email/address/marital_status/name）获得真实触发面。多值属性不失效，行为与 #136 一致。
- **精度风险**：抽取器可能把「观察/经历」标成 activity、「购买行为」标成 possession、「期望」标成 opinion；§23 的 30 条人工核对记录误判类型，词表描述据此收紧。歧义词不进别名表是同一取向。
- **旧库不兼容**：谓词键旧行与新 attribute 键新行互不失效；这是有意的「不猜历史」，代价是升级后旧数据的事实级失效面仍按旧口径。
- **窄触发面仍在**：没有 attribute 的 single 事实（favorite sauce、follower count、status）继续走谓词键；词表是否补 `status`/`count`/`favorite` 需下一轮语料测量，不在本 ADR 硬做。
