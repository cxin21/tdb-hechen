## 2. 背景与假设

R10（情感显著度）= `|valence| × arousal` 纯函数（`emotionSalienceOf`，
recall-signals.ts），双链接线：

- **钩子侧**：`auto-recall.ts` compareLex 平局链第 5 位（emotionWeight > 0 才激活）；
- **工具侧**：`memory-search.ts` secondaryOf 五元组第 5 位（原为不可达死代码，
  已随本预注册修复——见 §8；weight=0 时五元组第 5 位恒 0，修复行为逐位不变）。

当前权重 `memory.recall.emotionSalienceWeight` 缺省 0 = 可证恒等（全 0 项比较），
进预注册 A/B 队列，未过 A/B 不得置正（判官/抽取器同源偏差，永不单独放行排序变更）。

- **H1（主假设）**：`emotionSalienceWeight = 0.3` 时，情感相关查询的检索精度
  （主指标 P@5，见 §3）显著优于 `weight = 0` 基线。
- **H0**：两臂 P@5 无差异（Δ ≤ 0）。

机制依据：情感记忆（valence≠0 / 高 arousal）在 RRF 分数平局时应获得次级优先——
差异化能力（情感记忆 vs 中性记忆的检索优先级不同），当前排序信号空白区。

## 3. 指标定义（主指标唯一，事后不得更换）

- **主指标：P@5（按查询平均）** = 对每个情感查询，取注入/搜索 top-5 记录，
  命中判官标注 `rel ≥ 2` 的记录数 ÷ min(5, 该查询 rel≥2 标注总数)，对查询集求宏平均。
- **判官口径**：复用 D3 判官软轨（`scripts/judge-run.mjs`，rel ∈ {0,1,2}，
  标注池 `docs/superpowers/evals/judge/labels-*.jsonl`，2026-09-16 存量 142 条）。
- **标注固定法**：A/B 两臂共用**同一份**冻结标注（rel 标注不随两臂重跑判官）——
  评测对象是排序变化对固定真值的影响，不是判官对排序的反应。
- 次级观测（不参与通过判定，仅登记）：top-5 中情感记忆（|valence|>0）占比变化；
  非情感查询集的 P@5 不回退（外溢检查，预期恒等——R10 仅平局链生效）。

## 4. 情感查询集定义（选集规则冻结）

从判官标注池筛选满足**全部**条件的查询（queryId 粒度）：

1. 该查询至少 1 条 `rel ≥ 2` 标注记录的 valence ≠ 0（soul 列，生产读回判定）；
2. 该查询标注总数 ≥ 3（保证 P@5 分母有意义）；
3. 目标规模：**≥ 20 组**；若池内合格查询 > 20，取 queryId 升序前 20（不得挑优）；
   若 < 20，实验不启动（等数据）。

选集脚本一次运行输出 `runs/r10-ab-cohort.json`（含选入 queryId 与排除理由），
入 runs 归档（不入公开仓库），后续批次不得复选。

## 5. A/B 设计

| 项 | A 臂（基线） | B 臂（实验） |
|---|---|---|
| emotionSalienceWeight | 0（现状） | 0.3（预注册固定，不得调参） |
| 其余配置 | 逐位相同 | 逐位相同 |

- **切换机制**：权重承载于 `cfg.recall.emotionSalienceWeight`（config 三层：
  config-override.json > TDAI_LLM_* env > yaml，spec §3.2）。执行采用 Lane 2 hermetic
  同构路径：临时网关 :8423 + 临时库 + 每臂独立 boot 注入各自 config-override.json——
  **生产 yaml 全程只读**，跑完自清理。计划文档曾记 "MEMORY_R10_ABILITY_WEIGHT 环境变量"，
  实测代码无此 env——以 config 层切换为准（本条为登记的修订，不改判据）。
- **同标注池评判**：两臂对同一查询集各跑一次召回，与冻结标注比对得 P@5-A / P@5-B。
- **双链覆盖**：主指标走钩子侧（注入序，/v3 链路）；工具侧（memory-search 输出序）
  作为次级观测同法登记——死代码修复后两链 R10 项均可达。
- 执行脚本：`MemoryCore/scripts/r10-ab.mjs`（数据到位后按本预注册实现，实现只得做
  管道胶水，不得引入本预注册之外的过滤/加权逻辑）。

## 6. 终止条件（先冻结，含通过线）

按标注批次（judge-run 每日 04:00 timer）推进，每批次对冻结查询集复算两臂 P@5：

1. **通过**：ΔP@5 = P@5-B − P@5-A ≥ +5 个百分点（相对宏平均），且情感标注查询 ≥ 20 组；
2. **无差异终止**：连续 3 个批次 ΔP@5 ≤ 0 → 实验终止，判 H0 成立；
3. **判负**：情感标注 ≥ 100 组（池上限）仍未达通过线 → 实验终止，判 H0 成立。

任一终止分支触发即冻结结果，出报告归档 `runs/r10-ab-report-*.json`（不入公开仓库），
结论登记 CHANGELOG。

## 8. 附：R10 工具侧死代码修复（随本预注册一并入库）

`memory-search.ts` secondaryOf 五元组的第 5 位比较（`sb[4]` 情感显著度）原位于
无条件 `return sb[3] - sa[3]` 之后——**不可达死代码，工具侧 R10 项从未生效**
（钩子侧 compareLex 接线正确）。已移入比较链；weight=0 时第 5 位恒 0，行为逐位
不变（tsc 244 持平、tools 域 103 测试通过）。此修复是 A/B 双链覆盖的前提。

## 9. 判官同源偏差声明（预登记，非事后辩解）

判官与 R10 同源于 LLM 打分：判官 rel 可能对情感表达有系统性偏好，与 R10 加权同向，
有共同抬高 B 臂的风险。对冲：①主指标采用**标注固定法**（§3，判官不重跑）；②敏感性
分析（预登记）：报告"仅 valence≠0 记录子集"与"全量记录"两个 P@5 口径，若仅前者
提升而后者不动，结论降级为"证据不足"，不进入 §7 通过后动作。
