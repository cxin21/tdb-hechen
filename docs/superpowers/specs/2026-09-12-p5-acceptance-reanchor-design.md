## 2. 目标 / 非目标

**目标**
1. 在当前语料快照上重锚基线，重立一条"守得住、说得清在守什么"的 P@5 验收线。
2. 基准工作点由重锚 A/B 数据裁决（精排去留），不预设立场。
3. 漂移重锚触发条件写入协议，终结"每次漂移人工重立"。

**非目标**
- 不动分层指标体系（CC/CTR/SD 首版只建基线不设线，沿用 DS-EVAL-LAYERED-001）。
- 不改 golden 集 19 条查询与标注（标注集是 L1 record id，P@5 职权范围不变）。
- 不做分数归一化（BM25/cosine 量纲教训，已裁定弃）。

## 4. 选定方案（B）细节

### 4.1 步骤①：基准工作点裁决（数据驱动）

重锚日同语料同锚跑 **精排 off vs 相关度主导 on** 的 golden A/B：
- 工作点 = 实测 P@5 更优者（不得凭断言裁定）。
- 预注册判据：两者差 < 0.02 视为平手 → 取**关**（简单者优先，与关断矩阵先例一致）。
- 若"开"胜出，须同时登记分层指标（CC/CTR/SD）旁证无反向漂移（防 P@5 涨、分层面伤的形态变更漏判）。

### 4.2 步骤②：当前快照重锚基线

- 以重锚日 `configSnapshot.corpus` 为语料快照，归档双锚 run（惯例：runs/ 时间戳 + gitSha + 四配置数字一致校验）。
- README 锚点引用回填（惯例：只追加不改史）。

### 4.3 步骤③：立新线 + 漂移协议

- **新线 = 重锚基线 − 0.02**（沿用 0.325 时代的 margin 纪律；实施时以重锚实测基线代入，如基线 0.345 → 线 0.325 名义巧合重现也以实测为准）。
- 线的归属：平面层 P@5 体系（yaml 注释同步，替换 :88 处旧口径）。
- **漂移重锚触发条件**（满足其一即须重锚，方可比数字）：
  1. 语料条目数漂移 > 2%（相对重锚快照）；
  2. L1 排序语义配置变更（九通道权重 / 精排权重 / 门槛 / 分层预算）；
  3. golden 集或标注集变更。
- 重锚操作 = 重跑 §4.1–4.3（工作点复用上次裁决，仅基线与线刷新；工作点变更时全流程重走）。

1. 重锚 A/B 两份 run 归档在案（同语料快照、gitSha 一致、P@5 per-query 序列可复算）。

4. 漂移触发条件三条款全部落文档；下次漂移发生时按协议执行（演练留待真实漂移）。
5. 全量回归绿；分层指标基线（工作点下）随锚归档。
