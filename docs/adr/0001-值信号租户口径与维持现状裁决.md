# ADR-0001：值信号租户口径与维持现状裁决

## 背景

召回值信号审计（#8/#14 triage 轮）核实了四条被质疑为「缺陷」的现状行为。逐条复核后判定：其中大部分是**自洽的契约或低成本正确的取舍**，不应按 bug 修复；需要的是把它们显式成文，防止后续轮次重复质疑或误改。证据位置均已在票 #14 与实施方案 `p14.md` 核实（main @ e0ae1c9 时点）。

## 决策

### 1. 值信号租户口径 = default 桶契约（非疏漏）

- **现状**：`computeRecallValueSignals`（auto-recall.ts:1252-1280）生产路径固定读 default 桶（tdai-core.handleBeforeRecall 不传 profileIsolation）；工具侧 `isolationFilter` 缺省同样落 default 桶——两路同桶自洽。
- **裁决**：维持现状，定性为**契约**。值信号（fired 标签/moodSign/coreRefBoost）是「这条 query 触及了哪些长期在意的价值」的功能性信号，不需要 per-agent 精确租户；种子锚与手动锚集中 default 桶是主用法。
- **已知边界（记录在案）**：per-agent 化（PA）后自演化锚落在各 agent 桶，default 桶扇出副本不再更新 → 值信号对「演化锚」静默失效（表现为不 fired、coreRefBoost=0），不产生错误信号。
- **未来方案（记录，不实施）**：若启用 per-agent 值信号，方案 = 信号读桶随 `profileIsolation` 传参 + default 桶兜底合并；需同时审计 anchorEvidenceValences 的租户三元组口径，避免半迁移。

### 2. G-SIMMERGE（相似锚合并）缺省关

- **现状**：`similarMerge.enabled` 缺省 false；候选锚与既有锚相似命中时仅重算权重不新建的路径默认不生效。
- **裁决**：维持缺省关（config-first 铁律：缺省=逐位现状）。碎片锚治理走主道 = **#18（theme aliases + 去重粒度收紧）**；G-SIMMERGE 保留为实验开关，待 #18 上线后实测残余碎片率再评估是否转正。

### 3. current-feeling query 截断 1000 字维持现状

- **现状**：`tdai-current-feeling-injector.ts:73` 对 query `slice(0, 1000)` 后做感受匹配。
- **裁决**：维持现状。感受匹配是 label 子串命中，有效判据集中在前段；不截断只会放大 prompt 与匹配开销。若未来 label 命中率出现「尾部 query 才命中」的实证，再评估放宽。

### 4. 感受匹配否定盲区维持现状（R4）

- **现状**：`appraise` fired = `ctx.includes(label)` 纯子串，「不要碰数据完整性」与「坚持数据完整性」同命中。
- **裁决**：维持现状。fired 语义只表「触及了该价值」，不表立场；方向由锚 valence 承担（趋近/审慎），否定语境与锚语义不冲突。否定检测（分词+依存或 LLM 判定）成本远超收益，不做。

### 5. coreRef 精排因子 0.05 定位 = tie-breaker（显式化）

- **现状**：精排四因子 relevance 0.7 / timeProx 0.15 / significance 0.1 / coreRef 0.05——coreRef 权重最末，实际起并列决胜作用。
- **裁决**：定性为 **tie-breaker**（显式化其定位，不再被期待为独立质量信号）。0.05 vs 0.1 的校准实验归 **#2**（实验结论回填本 ADR 开放条目）。

## 不做清单

- 不改 `computeRecallValueSignals` 租户口径（契约维持）。
- 不缺省开启 G-SIMMERGE。
- 不放宽 query 截断。
- 不做感受否定检测。
- 不在 #14 范围内动精排权重（归 #2 实验定）。
