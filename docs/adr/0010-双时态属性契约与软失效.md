# ADR-0010 双时态属性契约与软失效：supersession 只在单值属性上成立

- 状态：已接受（2026-10-27，#136 实施；生产开关仍由 memory.write.supersession.enabled 控制）
- 关联：#134（W2 写时 supersession 首版）、#136（本决定）、#137（W1 并行召回通道）、docs/optimization-results.md §8/§9/§11

## 背景

#134 的 W2 把「同（subject, predicate）新值 ≠ 旧值」当作版本更新，把旧 L1 行整行写 `valid_end`。
LME90 全开档实测：turnCov −10.9pp（CI[−17.0,−5.7]），temporal-reasoning 桶因旧事件被删到拒答。
#136 复查定位两类根因：

1. **语义前提不成立**：supersession 成立的前提是属性为函数依赖（同一时刻只有一个值）。
   但抽取器的 predicate 是泛化谓词，实测被误失效的 140 条里绝大多数是
   `is considering` / `plans to try` / `likes` / `has` / `feels` / `replaced` 一类
   ——值之间不互斥，新值只是「又一条」而非「取代」。
2. **失效 = 硬删除**：读侧 `isOutsideValidityWindow` 直接过滤，行一旦失效就永久退出候选池；
   temporal 题需要旧事件仍在池里排序，而不是被删掉。

## 决定

1. **属性契约（cardinality）**：新增 `cardinality` 纯函数层，把事实分为 `single` / `multi`。
   判定优先级：显式标注 → 单值词表（计数/联系方式/个人档案；中英；英文卡词边界）→
   多值/模态词表（consider/want/plan/like/has/feels/is…；含屈折变体）→ 值结构线索（or/、/，）
   → 缺省 single（保覆盖，= #136 前行为）。
   **只有 single 允许 supersession；multi 是 additive，永不失效。**
   写侧在生产路径（l1-writer dedup update/merge、l1-extractor conflict）先做内容级判定；
   `cardinalityGate=false` 为回滚阀门（逐位 #136 前行为）。
2. **软失效（soft validity）**：读侧效期从「硬过滤」改为「排序特征」。
   future 恒丢；expired 的 relevance（rrfScore）乘 `SOFT_VALIDITY_PENALTY` 后继续参与
   组合精排（保留相关度序，不做池级块重排）——这是「效期作为融合特征」的最小实现。
   仅当查询显式问「现在/最新」（复用 #135 R3 detectPresentTemporalIntent）且池里存在
   **内容相关**的更新行（active `valid_start >= expired.valid_end` 且内容 token 有重叠）
   时才硬丢；任意新记忆不足以成为「取代者」。
   三路读口径按能力分层：钩子路可重排序 → 降权 + 条件硬丢；结论层放宽通道与工具路
   无法重排 → 只丢 future、保留 expired。`recall.validity.mode` 缺省 hard（逐位不变），
   soft 由配置显式开启。
3. **零删除红线不变**：失效只写 `valid_end`；不归档、不删除，历史可追溯。
4. **粒度**：行级失效的既有语义本票不改（事实级一行一事实是 #136 的次优先项）；
   soft 保留 + 契约门控已把「整行误伤」的后果从「永久丢失」降为「排序下沉」。

## 理由

- **先判该不该删，再谈删多少**：粒度细化只缩小破坏面；契约解决「删错」。两者都做，但顺序是契约优先。
- **失效是信息不是判决**：双时态的价值在于「旧值仍可追溯」，硬过滤把这个信息扔掉了；
  软失效让「新旧」成为可分级的信号，交给查询意图裁决。
- **缺省保守**：多值判定沿用泛化谓词线索，宁可少失效（additive）也不误删；
  真·函数依赖（粉丝数/价格/住址）仍走失效路径，knowledge-update 收益不被牺牲。

## 后果

- LME90（同 manifest/judge 配对）：W2 失效条数 140 → 0 ——**不是关掉 supersession**，而是
  该语料抽取出的 140 条「新值」全部落在泛化谓词上（is considering/plans to/likes/has/feels…），
  契约判定它们不是函数依赖，因此没有一条应当取代旧值；真·单值属性仍走失效路径
  （写面端到端测试 l1-writer.write-policy.test.ts「单值内容仍走失效」锁定）。
  knowledge-update / temporal-reasoning 桶回到 b1-off 水平；软失效在「关闭契约门」的对照档
  上恢复被硬过滤删掉的旧值证据（数字见 docs/optimization-results.md §11）。
- 生产：`memory.write.supersession.enabled` 仍缺省关；开启时 `cardinalityGate` 缺省 true，
  `recall.validity.mode` 建议 soft（本机 yaml 保持 hard，待生产语料复核后一行切换）。
- 遗留：事实级粒度（一条事实一行）与抽取器直接输出 cardinality 标注，留待后续票；
  多值词表是启发式，长尾谓词走缺省 single（可观测 reason 里可查）。
