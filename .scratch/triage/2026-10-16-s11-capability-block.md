系列：灵魂注入质量轮 R3（[S1]–[S11]）

## 现象（缺口）

六组件映射（docs/research/2026-10-16 §5.1）：TDB 缺「能力自我」——「我能做什么/常怎么做」（工具面、工作流偏好、领域专长）无身份层承载。MIRIX 记忆类型学中 procedural memory 是独立一类；Voyager 证明技能库=能力自我的持久层。当前 agent 能力断言只能靠 LLM 底座默认+system prompt 散文，可能与实际工具面不符（幻觉能力或漏报能力）。

## 第一性原理分析

能力断言失真有两类代价：过度承诺（声称会做但工具不存在→幻觉链）与自我设限（有工具面但不知道→能力浪费）。

能力块与价值锚同构（label：desc 的结构化身份条目），但真值来源不同——价值锚来自经历凝练（主观），能力块必须来自**工具面实况**（客观：已注册工具/成功使用史），否则直接制造身份层幻觉。写入路径应走「使用史统计+人工确认」双门，与 pending-adopt 同构。

## 方案（方向，低优先级）

- procedural 身份块：label+desc+证据（使用统计引用），渲染进 soul-identity 独立行（如「我的能力」）。
- 真值源：工具注册表 join 使用史（L1 work_fact 类记忆已含大量能力线索）。

## 验收标准（拍板后细化）

- 每条能力断言带使用史证据引用；无证据不注入（宁缺毋滥）。
- config 开关缺省关。
