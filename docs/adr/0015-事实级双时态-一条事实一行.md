# ADR-0015 事实级双时态：一条事实一行，失效只落在同（实体,属性）的单值事实

- 状态：接受（2026-10-29，#146 实施；生产开关 `memory.write.factRows.enabled` 缺省关）。**决定 2 被决定 7 局部取代**（2026-10-30，#166）：present-intent 值级遮蔽把「注入按 turn」收窄为「检索面与折叠预算按 turn，污染 turn 的注入单位降级为事实短语」；其余决定不变，故不新开 ADR（序号递增留给真正独立的架构决定）。

- 落点：`MemoryCore/src/core/record/fact-row.ts`（新）、`l1-writer.ts`、`fact-key.ts`、`supersession.ts`、`write-policy.ts`、`store/sqlite.ts`（`invalidateL1ByFactKey`）、`core/prompts/l1-extraction.ts`、`src/config.ts`、`scripts/lib/bench/facts.mjs` / `store.mjs`；#166 另落 `core/recall/fact-turn.ts`（`collapseFactRowsByTurn` 的遮蔽项）、`core/hooks/auto-recall.ts`、`scripts/eval-memory-bench.mjs`（`--prune-fact-sibling-index`）、`scripts/audit/r146-walkthrough.mjs` / `r146-lme-walkthrough.mjs`

## 背景

#136 把失效从「硬过滤/硬删」改成「软失效 + 属性契约」：只有函数依赖（single）属性允许失效，多值（multi）是 additive；失效只写 `valid_end` 不删除。
但它只解决了**该不该失效**，没解决**失效落在哪一行**——粒度仍是整行（一条记忆 = 一个 turn 的合并正文）。于是同一个 turn 抽出两条事实（如「粉丝数 1000」+「喜欢徒步」）时，第二个 turn 更新粉丝数仍会把整行写 `valid_end`，兄弟事实连坐退出检索面。
#136 票面明确把事实级粒度按「优先级低于 1/2」留作后续，并在 ADR-0010 后果里登记为遗留。

## 决定

1. **一条事实一行（方案 A）**：`planFactRows` / `planFactRowsFromMetadata` 把 `memory.metadata.factTriples`（或 `facts`）规整为事实行。
   - `content` = **父 turn 原文**（不是事实短语）：检索/BM25/注入因此与整行基线逐位相同，读侧按 `fact_of` 折叠回 turn 即零预算代价（见决定 5 与后果「v1 实测」）。事实短语存 `metadata.fact_phrase`（抽取器直出，缺省回落 `subject + " " + predicate + " " + value`），供审计与读侧按事实判效期；
   - `id` = 第 0 行沿用父 id，其余 `${父id}#f${n+1}`（`factRowIdOf`）——图边 / 引用 / evolve 边都按父 id 建，重编号会让引用悬空；
   - `metadata` 带 `fact_of / fact_index / subject / predicate / cardinality / fact_key`（`factRowMetadata`），旧值可追溯、事实级效期可在 metadata 里读；
   - `writeMemory` 返回父记录（= 0 号行 id），调用方零改动。
2. **写路径**：`factRows.enabled` 且本记忆抽出可用三元组时，**父整行不再落库**（事实行取代它）；dedup update/merge 的整行 `invalidateL1` / 归档对该类记忆一律跳过（爆炸半径从结构上消失）。
   写前按 `factKeyOf(subject, predicate)` 只失效 **cardinality=single** 的同键旧事实行；multi 永不失效。
   **失效时刻 = 新事实的有效起点**（`valid_start` → `occurred_at` → 写时刻兜底），不是写时刻。
   这条不是细节：读侧 soft 效期的「问当下才硬丢」判据是 `candidate.valid_start >= item.valid_end`，
   若 `valid_end` 记成 now（晚于新行起点），旧行永远判不出「被取代」，问当下的硬丢全部落空
   （#146 验收②）——走查脚本首版就栽在这里，见 `scripts/audit/r146-walkthrough.mjs` 注释。
   用新事实起点还让区间本身正确：柏林 `[3-02, 4-11)` → 慕尼黑 `[4-11, ∞)`；乱序写入产生倒置
   区间时读侧按 expired 处理（期望行为，不额外设防）。
3. **存储能力可选、但不静默降级**：`VectorStore.invalidateL1ByFactKey(filter, factKey, validEndIso)` 用 `json_extract(metadata_json,'$.fact_key')` 精确定位 + 隔离 filter。后端未实现该可选方法时 **loud warn 并跳过**，不回落整行失效——回落等于把本票收益静默撤回，还会重新制造兄弟连坐。
4. **抽取器直出 cardinality + phrase**：facts schema 增 `phrase` / `cardinality`（single=同实体同属性同刻只能一个值：城市/电话/价格/数量/状态/职位/住址/过敏；multi=可并存：喜好/计划/考虑中/症状/朋友/技能），prompt 明确「拿不准就省略」；`classifyCardinality` 启发式仅兜底。配置 `memory.write.factRows.{enabled,maxFacts}` 缺省关；`maxFacts` 未配时回落 `factKey.maxFacts`（config 不注入缺省值，避免静默覆盖用户的 factKey 配置）。
5. **读侧复用 #136 + 一处折叠**：效期判据完全复用 #136 软失效谓词（问「现在」时才在存在内容相关更新行时硬丢，问历史保留；expired 降权参与组合精排），不新增判据。
   唯一新增是**槽位折叠**：`collapseFactRowsByTurn`（`src/core/recall/fact-turn.ts`）在截断前把同一 `fact_of` 的多个命中折叠成一条（保留最高分、位置不变），auto-recall 与 memory-search 两条读路都接。
   理由是槽位口径必须与呈现口径一致：写面按事实存储，但"注入预算"的单位是 turn——同一 turn 的 N 条事实若各占一位，k=5 会被单轮吃光。
6. **属性键归一只做通用归一 + 少数语义族**：`factKeyOf` 现在做大小写/空白/首限定词/所有格/尾标点归一，并对居住地/职业/电话/年龄/价格五族做同义映射（表外不猜，宁缺毋滥）。
   但这在真实语料上 **0.0% 收益**：1796 三元组 / 1461 个 (subject,predicate) 对，跨 turn 重复 219 个，归一并列前后完全相同——语料谓词是自由文本（`is considering` / `plans to` / `likes`），同义表打不到。
   故不宣称"已修复属性碰撞"：真正的修法在抽取期（抽取器直接输出 canonical attribute），列为遗留。
   **#167 已按该遗留落地**：抽取期直出封闭 attribute，键改 `(normSubject, @attr:<attribute>)`、无 attribute 才回落本条谓词口径；基数优先级改为 attribute > 显式 > 启发式。谓词同义族保留为无 attribute 时的兜底，不再作为主修复路径。见 ADR-0016。

7. **present-intent 值级遮蔽（#166，方案②的读侧变体）**：折叠事实行的同时，把**池内已过期行**（不论硬丢/降权）当污染源；其所属 turn 的存活行改用**自己的 `metadata.fact_phrase`** 注入（`displayContent`），短语缺失或短语仍含任何被取代旧值的行直接剔出注入——宁可少给一条证据，绝不把旧值塞回上下文。只在 `presentIntent`（`detectPresentTemporalIntent(userText)` 命中）且 `excludeInvalidated !== false` 时启用；问历史逐位不变（旧值仍可回溯）。
   - **混合意图不遮蔽**（`valueMaskIntent = presentIntent && !detectHistoryTemporalIntent(userText)`，`src/core/tools/recall-signals.ts` 的 `HISTORY_TEMPORAL_RE` 认 `before/previously/used to/just started/之前/当初/刚开始` 一类标记）：既问「刚开始」又问「现在」的题，标准答案横跨旧值与新值，遮蔽会把含旧值的 gold turn 整条剔出。LME90 深池实测该形状（`031748ae`，我先带几个工程师/现在带几个）在无闸时 turnCov@5 0.5→0；加闸后恢复 0.5，转成正确答案该给的证据面。`presentIntent` 本身不改，仍原样喂 #136 的硬丢判据。
   - **为什么不是方案①（文本级 diff 遮旧值）**：需要值级 diff，最容易误伤；也不是方案③（写入期把单值属性升为独立 turn）：那会改存储粒度与图边归属，本票不动写面。
   - **为什么污染源是"池内 expired"而不是"硬丢行"**：soft 档的 related 是 `contentTokenOverlap`（CJK 3 字+/ASCII 4 字+ 词重叠），属性更新前后原文常无重叠（「我住在柏林，最近迷上摄影」vs「我上个月搬到慕尼黑了」），过期行通常只被 demoted 降权而不硬丢；只认硬丢行会漏掉最常见的中文更新链。
   - **默认档（`excludeInvalidated=true`，config 缺省）同样需要遮蔽**：hard 的过期行在折叠**之后**才被 `applyExclusion` 过滤，折叠时父原文仍在池里——故污染源计算必须在折叠前、且 true/soft 两档都算。
   - **作用域**：只改钩子注入路（`searchHybrid` → auto-recall）；工具路 `memory-search.ts` 的折叠仍返回父原文（工具返回结构化行，用户自行判读），列为遗留而非本票验收。
   - **遮蔽后仍要能归因到 turn**：注入文本换成短语后，bench/日志再靠「文本→turn」反查必失配。故 `RecalledMemory.turnId` 直接从 `searchResult.metas[i].recordId` 去掉 `#f<N>` 后缀透传，且折叠路径（`collapseFactRowsByTurn`）同时折叠 `metas`（落选兄弟位置置 `undefined`，与 `lines/scores` 保持平行）——否则折叠一开 `metas` 整条缺席，turnId 全空。这是可观测性修复，不改检索结果。
   - **遮不到的两条残留（自觉放弃，不当"已修"）**：①**跨 turn**——遮蔽只作用在被污染 turn 的存活行；若**新值所在的更新 turn**原文自己复述了旧值（「我上个月从柏林搬到慕尼黑」），该行仍逐字注入。要修就得做全局值级 diff（回到方案①的误伤面），本票不做，靠抽取器输出干净短语逐步收敛。②**旧值读不到时不校验**——过期行既无 `fact_value` 也无 `factTriples` 时只知"这个 turn 脏"、不知道脏值是什么；此时存活行的短语无条件注入（只有缺短语才剔），即校验退化为"信短语本身"。旧库（#166 之前写入）没有 `fact_value`，这一形状在真实历史数据上会命中。③**混合意图按字面仍会漏**——`valueMaskIntent` 跳过的问句（presentIntent 为真但带 before/之前/刚开始）里兄弟行仍以父原文注入，旧值照旧出现在上下文；取舍理由见上（LME90 深池 `031748ae` 不跳过就掉 0.5），验收①因此只在**纯 present** 问句上成立。④**present-intent 对 soft 档是收紧**——池内过期行一律不注入，等价于对这些 turn 硬丢；#136「过期只降权、内容相关才硬丢」在 present 问句上不再逐位成立。

## 理由

- **粒度是消除爆炸半径的唯一手段**：契约已经回答「该不该失效」；同一 turn 里单值属性真更新时，只有把失效范围收缩到「同（实体,属性）的那一条」才能不伤兄弟事实。
- **单值/多值必须按事实判，不能按 turn 正文判**：正文级判据会把整个 turn 判成 single（连坐）或 multi（该失效的不失效），两种都错。事实行让 `cardinality` 有明确载体。
- **不回落整行**：这是有意的「宁可少失效也不放大」——与 #136 的保守取向一致；后端缺能力是可观测的运维缺口（warn + 文档），不该由数据正确性买单。
- **0 号沿用父 id**：让写面返回父记录、图边/证据链不动，是本票能做到「接线零改动」的关键。
- **开启成本可量化**：一条事实一行让 L1 行数上升（每 turn 最多 maxFacts 行），检索预算仍是 5 行；因此评估必须固定在深池（#135 约束），否则事实行会被 `candidates=12 + minScore=-2` 剪光，误判「事实级无收益」。

## 后果

- **行为**：开启后旧事实行 `valid_end` 落库（= 新事实有效起点，区间首尾相接）、同 turn 多值事实行保持 active（真实 sqlite 端到端测试 + 生产语料走查钉住）；关闭时逐位现状（一个记忆一行）。
  与 #136 整行路径的差异知情保留：整行失效仍记 now，事实行记新值起点——事实级才有「区间」可言，整行路径不重排序，now 不影响其判据。
- **回归保护**：`fact-row.test.ts` / `l1-writer.fact-rows.test.ts` / `invalidate-l1-fact-key.test.ts` / `l1-extractor.fact-rows-guard.test.ts` / `config.write.test.ts` / `l1-extraction.facts.test.ts` / `fact-turn.test.ts`（折叠，5 条）/ `fact-key-canonical.test.ts`（归一，5 条）共 47 条。
- **生产缺省关**：抽取器 `phrase/cardinality` 质量未在真实语料复核前不打开；打开后该类记忆不再走整行归档（有测试钉住 target_ids 仍保留给图边）。
- **v1 实测（否定）**：LME90 b1-off 配对（n=90，同 manifest/judge）：整行基线 turnCov@5 = 78.4%，事实行档 = 68.0%（配对 Δ = −10.38pp，CI95 [−19.92, −0.77]），偏好桶 93.3%→55.6%。诊断档把行预算放到 10 并按 turn 折叠后回到 72.4%（对事实行档 +4.41pp，CI95 [+0.77, +9.00]，对基线仍 −5.98pp）→ 槽位饥饿只解释约 4 成，另 6 成是"注入的是事实碎片、丢了 turn 语境（说话人/时间/上下文）"。v1 的 `content = phrase` 是错的：详见 `MemoryCore/.eval-data/bench/r146-diagnostic.md`。
- **v2 修正（本 ADR 决定 1/5/6）**：行 `content` 改回父 turn 原文 + 读侧按 `fact_of` 折叠 ⇒ "存储按事实、检索与呈现按 turn"，检索面与整行基线逐位相同（构造上不涨预算、不丢语境）；bench 侧 `buildFactRowRecords` 同步同口径。剩下的事实级收益仍取决于真实语料的属性碰撞面（决定 6 的 0% 发现），故生产开关保持缺省关，但**"开了可用"由此变成构造性质而非实测结论**。
- **后端能力差**：事实级失效依赖 `invalidateL1ByFactKey`（sqlite 已实现，含 `json_extract(metadata_json,'$.fact_key')` 表达式索引）。**TCVDB 部署两头都没有**（`store/tcvdb.ts` 既无该方法也无 `invalidateL1`）→ 该部署下打开 `factRows` 只会 loud warn、永不失效，必须进开关台账：TCVDB 上不要开。
- **真实语料触发面**：LongMemEval knowledge-update 切片（15 case / 395 三元组，facts-v3 抽取）基数分布 single 130 / multi 265；同键跨轮多值 52 个键里只有 **16 个是 single** → 事实级失效的真实触发面窄（约 4% 的三元组），收益前提是「同属性被反复提到且被判为单值」，与抽取的谓词稳定性强耦合（见 docs §22.3；谓词归一的 0% 收益见 §22.6）。
- **v2 值级泄漏（#166 已修，决定 7）**：行 `content` = 父 turn 原文后，旧值文本会随**兄弟事实行**回到注入面——`turn-1`（居住=柏林，single）被失效，同 turn 的 `turn-1#f2`（爱好=摄影，multi）仍 active 且 content 同为「我住在柏林，最近迷上摄影」，于是"问当下"仍会注入含柏林的文本：**行级正确性成立（旧事实行确实失效），值级"不再出现在上下文里"不成立**。#166 用决定 7 的 present-intent 遮蔽补上这一层：
  - 合成走查（`scripts/audit/r146-walkthrough.mjs`）15/15 PASS：present 注入 3 行，柏林消失、改为「用户最近迷上摄影」等事实短语；问历史仍含「我住在柏林，最近迷上摄影」。
  - 真实语料走查（`scripts/audit/r146-lme-walkthrough.mjs`，knowledge-update case `18bc8abd`，问句「What brand of BBQ sauce am I currently obsessed with?」/「… was I obsessed with before?」）8/8 PASS：问当下注入无被取代的 `Sweet Baby Ray's`、污染 turn 的 2 条存活行改注入自身事实短语（`Planning to host another backyard BBQ soon` / `Friend Emily brought grilled pineapple…`）、并召回新值 `Kansas City Masterpiece BBQ sauce`；问历史注入仍含旧值。
    原脚本默认 case `50635ada`（United 里程）已不适用：facts-cache 在 2026-10-30 重生成成 facts-v3 后，抽取把旧值/新值落成**不同谓词**（`User.eligible_for_status` vs `User.reached_status`），写侧「同 fact_key 才失效」不再触发，该 case 的判据会静默 SKIP。换 case 前用 `.eval-data/bench/findcase.cjs` 扫同键更新面（500 题里 46 题有同键不同值；KU 里 `18bc8abd` 5 次最多）；问句用 `--present/--history` 传，因为 facts-cache 谓词随 promptVersion 变。
  - 代价与边界：遮蔽是**行级替换/剔出**，不重写父原文、不改写面；被遮蔽 turn 的上下文（说话人/时间/相邻事实）丢失，故只在 present-intent 触发，且短语缺失/仍含旧值时不注入该行（宁缺毋滥）。
- **图边归属**：事实行模式下 update/merge 不归档，旧边不级联清理（evolve 链逐轮累积）；且边源恒为父 id = 第 1 条事实行，过期的是第 N>1 条时属边归属错配。读侧效期过滤兜底，故列为遗留而非阻断。
- **遗留**：事实级相关性排序（cardinality 进通道内打分）未做——#135 R2 已证加性 validity 权重无效，本票只做候选阶段的事实行 + 写时精确失效。
