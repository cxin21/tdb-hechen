# 分层召回评估框架 · 设计

> 文档标识：DS-EVAL-LAYERED-001
> 版本：v1.0（设计稿——先设计后实施，本文档不含实施代码）
> 日期：2026-09-11
> 议题背景：RV2-3 golden 重锚归档实测——分层+结构通道形态 P@5=0.160 < 验收线 0.325，2x2 归因矩阵（纯基线 0.345 / 校准无精排 0.285 / 精排开 0.140-0.160）将伤害源定位为精排结构因子；但该归因仍以 P@5 为唯一量尺。本设计回应的议题是：**P@5（标注词命中）是平面召回的指标，分层召回的价值（结论覆盖率 / 信息密度 / 来源多样性）不在 P@5 的度量范围内**——需要一个与 P@5 并行的分层质量评估框架。

---

## 1. P@5 的适用范围与局限

### 1.1 P@5 度量什么

golden replay 的 P@5 = 前 5 名检索结果中命中"标注相关记忆集"（人工标注的 L1 record id 集）的比例。它度量的是**平面召回排序**的能力：给定 query，九通道融合排序能否把相关 L1 记忆排进前 5 名。

### 1.2 P@5 看不见什么（分层召回的四个盲区）

| 分层召回的价值 | P@5 为何看不见 |
|---|---|
| **L2 结论直接回答主题** | golden 的标注集是 L1 record id 集；结论（work_fact / scene block summary）不在标注集内。结论块注入**不经过 L1 排序**，其"是否命中主题"对 P@5 是零贡献——命中了不加分，缺席了不扣分 |
| **注入形态的信息密度** | P@5 只看前 5 名 id 是否相关，不看每条注入内容的浓缩程度。一条 200 字的结论与一条 20 字的碎片在 P@5 里同价 |
| **多来源结构（结论+经验+图邻居）** | P@5 对来源分布无感：5 条全 episodic 与 2 结论+3 经验的混合注入，只要 id 集相同，P@5 相同 |
| **结论常驻的 cache 友好与稳定性** | P@5 是单点量测，不度量注入块跨轮稳定性（幂等结论层的核心价值） |

### 1.3 实证证据

- golden 双锚（R7 前后）：前锚 `runs/2026-09-11T12-41-28.json`（sha 037f69d）与后锚 `runs/2026-09-11T13-09-41.json`（sha 6a3cd77）P@5 **逐位同值 0.210**——分层对 L1 排序零变化（不变式），同时说明**双锚实验对分层效果本身是盲的**：注入形态变了，P@5 一字不动。
  - **口径说明（2026-09-12 复审更正）**：`mismatchCount=0` 是 **offDeterminism 口径**（同一锚内 OFF 两趟 replay 结果一致），并非跨锚比对量——原文把两者混写为"双锚 mismatch=0"系失实。跨锚 P@5 同值（0.210）系**另行独立复算成立**：两锚各自 replay 出的 P@5 与 mismatchCount 独立计算后比对，0.210 逐位同值这一跨锚结论不受影响。
- RV2-3 的 0.125 vs 0.345 对比中，P@5 能定位"精排结构因子伤害平面排序"，却**无法回答"分层层本身贡献了什么"**——这两个问题必须由两套指标分别回答。

### 1.4 结论

P@5 保留其本职：**平面召回排序的回归门**。分层召回的质量裁决需要新指标（§2）。

## 2. 三新增指标设计

### 2.1 结论覆盖率（Conclusion Coverage, CC）

**定义**：L2 结论层对 query 主题的覆盖比例。

```
CC = 有主题相关结论注入的 query 数 / golden query 总数
```

- "主题相关"判定口径：**复用 golden 的标注词口径**——结论文本（work_fact content / scene block summary）含该 query 标注词集中任一词（子串、大小写不敏感），或结论的 sceneName 命中该 query 的标注场景（见 §3.1）。
- 分母用 golden query 总数（全量口径）；同时报告条件口径 `CC' = 覆盖数 / 结论层非空的 query 数`（层内命中率）。
- 语义：CC=0 表示分层第一层从未接住任何主题（分层形同虚设）；CC 高且 P@5 低，说明"结论在回答主题、平面排序在拖后腿"——正是分层设计的预期分工形态。

### 2.2 信息密度（Information Density, ID）

**定义**：单位注入 token 的信息量，以"结论/经验 token 构成"为核心分量。

```
ID 分量一 · 结论 token 占比  CTR = 结论块字符数 / 注入块总字符数
ID 分量二 · 平均行密度        ALD = 注入块总字符数 / 注入行数
ID 分量三 · 信息比（可选，引入权重后启用）
          IR = (w_c × 结论 token 数 + w_e × 经验 token 数) / 注入 token 总数
```

- token 估算口径：CJK 字符按 1 字符 1 token 近似、ASCII 按 4 字符 1 token（评估口径固定即可，不追求精确 tokenizer——**比较意义大于绝对意义**）。
- 权重起点：w_c=2、w_e=1（结论为浓缩持续态，同等 token 信息量更高）；**首版只报告不加权的 CTR/ALD 两分量**，IR 权重经首批实测数据校准后再启用——避免重蹈"给分数化妆"（量纲未实证前不合成单一分数）。
- 语义：分层设计预期 CTR > 0 且结论块短（ALD 因结论前置而下降或持平）——"更少 token 承载更多主题覆盖"。

### 2.3 来源多样性（Source Diversity, SD）

**定义**：单次注入的来源分布。

```
SD = 注入行按来源分类的分布向量 + Shannon 熵 H = -Σ p_i × log2(p_i)
```

- 来源分类（从注入行标注解析，与现有标注体系一一对应）：
  - `L2 结论`：`[结论|...]` / `[结论]` 行
  - `L1 九通道`：无补池标注的经验行（episodic / work_fact 等）
  - `scene 补池`：`[scene:名]` 行
  - `value 补池`：`[value:锚]` 行
  - `graph 补池`：`[graph:...]` / `[graph:ppr:kind]` 行
- 报告：每 query 分布向量 + golden 全集分布均值 + H 均值。分层设计预期：开启分层后 `L2 结论` 分量 > 0，且补池来源分布可观测（当前 golden replay 完全看不见这些来源的存在）。

### 2.4 指标性质约定

| 指标 | 类型 | 绝对门槛 | 裁决方式 |
|---|---|---|---|
| CC | 覆盖率 ∈ [0,1] | 首版不设 | 前后锚对比 + 工程判断（宁缺毋滥原则下 CC 低不必然是坏事） |
| CTR/ALD | 构成比 | 首版不设 | 前后锚对比，登记基线 |
| SD/H | 分布/熵 | 首版不设 | 分布可观测化，异常来源占比（如补池行淹没主检索）人工判读 |

三指标均为**观测性指标**（先让分层效果可见），非验收门（不给分层设数字门槛——分层价值含人工目检维度，spec DS-RECALL-LAYERED-R7-001 §4 的人工验收保留）。

## 3. 计算方法与数据来源

### 3.1 golden replay 可产出性矩阵（零后端新增约束的逐项核验）

| 指标 | 现有 replay 输出可直接推导？ | 所需数据 | 采集方案 |
|---|---|---|---|
| SD | **是** | 注入行文本（行标注自证身份） | 方案 A/B 均可（见 3.2） |
| CTR/ALD | **是** | 注入行文本 | 同上 |
| CC | **否**（现有 replay JSON 只有 L1 off/on 排序与 precision5，无结论层信息） | 每 query 的结论层选择结果 + 判定标注 | 方案 A 零改动可推导；方案 B 需一次性标注 |

### 3.2 两个采集方案（均为评估侧，零后端改动）

**方案 A · 纯函数离线重放（推荐）**
- 依据：L2 结论层选择是**纯确定性函数**（`selectL2Conclusions`——只依赖 query/候选/token 集，无时钟无随机，DS-RECALL-LAYERED-R7-001 实现已钉死此性质并有 34 断言单测背书）。
- 做法：评估脚本直接导入该纯函数，用 golden query 集 + 评测语料的 scene_index.json + work_fact 语料行离线重放结论选择，逐 query 得到结论集 → CC / CTR / SD 全部可算。
- 成本：一个评估脚本（evals 目录，非后端）；语料快照复用 golden 归档的 configSnapshot 口径。
- 风险：重放的是"选择函数"而非端到端注入链路（幂等缓存、预算切分的组装形态不在重放内）——CC 度量不受影响（选择结果一致），CTR/SD 若需端到端实证则叠加方案 B。

**方案 B · 注入快照采集（端到端实证，与 A 互补）**
- 做法：golden 脚本增加一个"注入快照"采集点——对每 query 触发一次注入链路（或读取注入块导出），把最终注入行文本落盘归档（与现有 runs/*.json 同目录）。
- 成本：采集脚本一次开发 + 每 query 一次注入链路调用；CC 判定另需 golden 配置为每 query 增加可选 `expectedScenes`（人工一次性标注，30 query 量级，成本低）。
- 定位：A 是日常快速口径，B 是收口/争议裁决口径（端到端所见即所测）。

### 3.3 计算流水线（设计态）

```
golden query 集 ──► 方案 A 重放（纯函数）──► 结论集 ──► CC / CTR(A 口径) / SD(A 口径)
        └──────────► 方案 B 注入快照 ──────► 注入行 ──► CC(标注判定) / CTR / SD(端到端口径)
现有 runs/*.json ────────────────────────► L1 排序 ──► P@5（不变，平面回归门）
```

归档纪律沿用现有 golden 双锚惯例：每次分层相关改动跑前/后双份，指标值写入归档 JSON（新增 `layeredMetrics` 字段，向后兼容——旧归档无此字段不报错）。
> **2026-09-12 追记（A1 写副本纪律）**：`layeredMetrics` 改落旁挂副本 `<原名>.layered.json`，**归档原档永不改写**（历史事故：失败轮原地覆盖 12-11-49 指标，靠 git 还原）；读取方双源兼容（原档内嵌 / 旁挂副本），缺副本抛错。同批新增 **CC 塌方侦测线**（相对上一锚降幅 >50% 红牌，阈值常量 CC_COLLAPSE_THRESHOLD=0.5，3 锚带宽 0 校准）。

## 4. P@5 与新指标的关系（两套并行）

### 4.1 分工矩阵

| 变更类型 | 回归门 | 评估指标 |
|---|---|---|
| L1 排序语义改动（RV2 精排、九通道权重、门槛调整） | **P@5**（现有验收线 0.325 体系不变） | SD/CTR 仅作旁证 |
| 分层注入形态改动（R7 及后续：结论层选择/预算切分/注入标注） | 既有 34 断言单测（退化安全/幂等/预算边界） | **CC / CTR / SD**（前后锚对比） |
| 混合变更（既动排序又动分层） | 两套同跑，各自口径各自裁决 | 同左 |

### 4.2 并行规则

- **不合并**：三新指标不与 P@5 合成任何单一分数（量纲不可比是 RV2-1 已实证的教训——BM25 与 cosine 的前车之鉴）。
- **不互判**：P@5 下降不否决分层指标改善，反之亦然。
- **冲突登记**：两套指标反向漂移时（如 P@5 降而 CC 升），登记为"**形态变更**"（injection-form change）而非"退化"——归因矩阵拆解到层（平面层归 P@5、分层层归 CC/CTR/SD），由队长按归因结果裁决；本设计不预设裁决公式（先设计后实施——实施时以首批双锚数据细化）。
- **验收线归属**：0.325 验收线属于平面层 P@5 体系；分层指标首版只建基线，不设线。

### 4.3 对 RV2-3 STOP 的回溯意义

以本框架回看 RV2-3 归因矩阵：纯基线 0.345 / 精排开 0.140-0.160 量得的是**平面层伤害**（P@5 职权范围内，归因有效）；但"分层+结构形态"的独立贡献（CC/CTR/SD）当时无指标可量——归因矩阵的第三维是盲的。本框架补上该维度后，未来同类 STOP 裁决可有完整的 2x2x2 证据面。

## 5. 与 wiki golden 的关系

- **wiki golden 的 P@5 体系完全不变。** 本设计的全部指标（CC/CTR/SD）与采集方案仅针对**记忆召回**（td-agemem 的 L1/L2 分层注入）。
- 两条链路物理隔离：wiki 检索走 wiki /search（wiki 语料、wiki 标注集、FTS5+向量 RRF、内容 sha256 增量对账），记忆召回走 td-agemem recall 链路（九通道+分层）——数据源、标注集、归档目录、验收线互不交叉。
- 共享的只有**方法论纪律**：双锚前后对照、关断矩阵（每通道关断=基线逐位）、逐位断言、归档留痕——这些纪律在本设计中逐条沿用（§3.3 归档、§4.1 单测门）。
- 明确禁止：不得以"统一评估"为由把 wiki 语料或 wiki 标注词引入记忆召回指标计算，反之亦然（来源可追溯纪律——指标块须标注来源体系）。
