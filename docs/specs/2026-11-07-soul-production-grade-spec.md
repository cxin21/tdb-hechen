## Problem Statement

这套自维护人格层已经能跑：10 分钟一轮，从对话事件里长出人格、算出心境、写进注入前缀；生产上 3 个租户每轮在跑，注入快照实测 5068 字符。但它现在不是「一个人」，是一台记录仪。

1. **卡上没有「人」的字段**。`SOUL_LAYERS` 是 voice / identity / self / values / boundary / relationship / narrative / method 八层，没有名字、没有形象、没有特质轴、没有使命、没有自传体。八层都在回答「我怎么判断」，没有一层回答「我叫什么、我长什么样、我脾气如何、我这段时间在过什么日子」。
2. **卡里 92% 是流水账**。主租户 285 条人格里 relationship 157 + self 106 = 263 条（92.3%），identity 7、voice 5、narrative 3、values 6、boundary 1；稳定人格不足 8%。渲染按层拼行，层与层之间没有关系——人不是八行列表。
3. **会长出来的东西会被自己丢掉**。事件史派生的事实按「本轮 7 天窗口内是否还在」判存活，窗口滑过即永久冻结：生产 232 条事件史事实只有 47 条活着（20.3%），190 条 frozen 的账本 gates 全是 `["episode_history"]`。
4. **两套人设互不相认**。Panel 表单的名字/描述/角色定位/规则存 `meta_agents`（`name`/`description`/`prompt` + `metadata_json.ui.role_prompt|rules_prompt`），人格卡存 `soul_persona` + `core_memory`；两套之间零代码通路——人格层没有任何一处读这两个字段。生产 6 个 Agent 的 `prompt` 全为 0 字符、role/rules 全为空串——声明通道存在但从未被用过。
5. **注入结构从根上与「一个人」相反**：每轮重拼前缀，人格没有会话内同一性（同一场对话里卡可能变三次）；情绪、人格、关系混在同一段预算里互相挤；注入总门还耦合在「存储方法是否存在」上。

> 上列数字是**改造前存量**，用于说明为什么要换引擎；按本轮裁决它们将被清空，不作为新架构的输入。

## Solution

一句话：**一个入口（表单 = 人物设定）、一张卡（会话开始时定稿）、一个漂移算子（带权特质缓慢趋近）、两条注入通道（会话初始化全卡 / 每轮少量）、一次清库重生。**

### 1. 人物设定：Panel 表单是唯一人工入口

表单只收「关于自己的稳定声明」六项，一格不多：

| # | 字段 | 形态 | 上限 | 进卡的区块 |
|---|---|---|---|---|
| 1 | 名称 | 文本 + 自称（`name` / `pronoun`） | 20 字 | 名称 |
| 2 | 形象 | 一段具象自述（屏幕上的样子、气质、呈现方式） | 200 字 | 形象 |
| 3 | 说话方式 | 自由文本：句长、是否用表格、怎么称呼对方、少用什么 | 400 字 | 说话方式 |
| 4 | 使命 | 一句长期取向，**禁写具体项目/本周任务** | 60 字 | 使命 |
| 5 | 特质 | 种子标签 + 初始权重（如「迷糊 1.0」），落库时换算成 6 轴初值；此后由经历缓慢漂移 | ≤5 个种子标签 | 特质 |
| 6 | 红线 | 逐行，一行一条，逐字保留 | 每行 ≤120 字、≤ `REDLINE_MAX_ROWS`(30) 行、总字符 ≤ 2600 | 红线 |

**不进表单**（只能由经历长）：价值观与品格（并入特质权重）、关系史、自我史、关于对方、自传、未完的事、当下心境。理由一句话：能写进表单的只有「关于自己的稳定声明」，写不了「我经历过什么」；把经历写成声明就是回到记录工具。

**可扩展**：字段集带 `schema_version`，后续加字段按「旧行缺字段 = 未设」处理，不做数据迁移；但**首页只这六项**。

**存储（唯一新表，不与现有表重复职责）**

```sql
CREATE TABLE IF NOT EXISTS meta_agent_persona (
  agent_id         TEXT PRIMARY KEY,
  team_id          TEXT NOT NULL,
  name             TEXT NOT NULL DEFAULT '',
  pronoun          TEXT NOT NULL DEFAULT '',
  self_image       TEXT NOT NULL DEFAULT '',
  voice            TEXT NOT NULL DEFAULT '',
  purpose          TEXT NOT NULL DEFAULT '',
  traits_json      TEXT NOT NULL DEFAULT '[]',  -- 种子 [{label, weight}]；方向由定义推导，见 §3
  redlines_json    TEXT NOT NULL DEFAULT '[]',  -- [{text, active, created_at}]
  schema_version   INTEGER NOT NULL DEFAULT 1,
  fingerprint      TEXT NOT NULL DEFAULT '',    -- sha256(name|pronoun|image|voice|purpose|traits|redlines)
  updated_at       TEXT NOT NULL
);
```

分工一句话：**这张表只存「设定」；`soul_persona` 只存「经历」（带时间区间的观察事实）。两者不互为副本，也不合并成第二种表。**

**名称同源（F7）**：表单的 `name` 保存时**写回 `meta_agents.name`**，同一事务、单向为准（`meta_agents.name` 不作为输入回写表单，避免双写）。列表显示名与自称永远同一个字符串。

**旧字段退役（F6）**：`role_prompt` / `rules_prompt`（存于 `meta_agents.metadata_json.ui`，文本再 join 成 `prompt`）在数据升级后**连字段连读写路径一起删除**——表单六项已能替代它们（红线 ← rules，使命 + 说话方式 ← role）。调用方不再自行拼岗位说明，改为取卡（§4）。本仓保留的只有「岗位职责一句」这一条元数据，且由使命派生、只读。

### 2. 一张卡：区块 × 来源

| 区块 | 来源 | 变更时机 | 注入通道 |
|---|---|---|---|
| 名称 / 形象 / 使命 / 说话方式 / 红线 | 设定（锚点） | 用户改表单；红线另可由用户拍板原话追加 | A 会话初始化 |
| 特质 | 设定种子 + 6 轴状态（经历漂移）+ 标签视图（可增可并） | 每 tick，缓慢 | A 会话初始化 |
| 关于对方（human） | 经历（对话原文） | 中速，按新证据并入 | A 会话初始化 |
| 关系摘要 | 经历（episode/承诺/情绪对象，按对象聚类） | 每 tick | A 会话初始化 |
| 自我史摘要 | 经历（带生效区间的观察事实） | 每 tick | A 会话初始化 |
| 自传 | 推导（月度重写） | 月度 | A 会话初始化 |
| 未完的事（openLoops ≤3） | 经历（open promise / 被打断的任务） | 每 tick | **B 每轮提醒** |
| 当下心境 | 经历（情绪积分 / 底子行 / 对象立场） | 每 tick | **B 每轮** |
| 元数据 | 推导（cardVersion / cardHash / sources / drift） | 每 tick | 不进 prompt |

「合并」只发生在**特质**这一列：设定给初值，经历改数值。文本设定（名称/形象/说话方式/使命/红线）**从不被经历改写**，只允许「追加限定」（见 §3）。

**`core_values` 退场（F1 裁决）**：原先由它供料的「价值锚 / 重要的人 / 我的品格」三块，改由**特质标签**（品格与取向）、**`human` 层**（关于对方）、**关系史**（重要的人）分别承担；`core_values` 整表删除、`anchor-growth` 整段逻辑删除、Panel values 读面下线。判据：`core_values` 的读写点归零，且卡内三块仍有内容（空库起步时由表单红线 + 特质种子 + 首轮 human 观察填上）。

### 3. 特质：固定 6 轴 + 开放标签（标签是空间里的方向，不是独立权重）

**为什么不是「一张更大的词表」**：词表越长，标签越互相相关（16 因素收敛到 5 因素，正是因为相关因子不可复现）；而「每个标签一个独立权重、Σ=1」这种表示，每加一个标签就稀释所有已有标签——**「会扩展」和「可测漂移」在权重单纯形上是互相排斥的**。

**两层表示**

1. **轴（固定 6 个，不随经历新增）**：亲和 / 主导 / 严谨 / 开放 / 稳定 / **守界**。状态 `trait_state ∈ [-1,1]^6`，是漂移的唯一载体：有边界、有账本、可监测。守界 = 诚实-谦逊（HEXACO 第 6 因子）：不虚报、不甩锅、不越权、认错不辩解。
2. **标签（开放，可增可并）**：每条 `{label, definition, direction[6], evidence, firstSeen, lastSeen, status}`，`direction` 为单位向量；**激活度** `act_i = clamp((⟨state, d_i⟩ + 1) / 2)`，渲染时对活跃集归一。标签不单独存权重，是「读出来的视图」。

**轴能不能覆盖所有特质？不能——但「不够」必须可测**

- 任何有限轴集都覆盖不了全部特质。Big Five 之上还有可复现的第 6 因子：诚实-谦逊（HEXACO；德语词汇学研究独立复现出六因子结构，[German lexical personality factors, 2006](https://doi.org/10.1002/per.597)）；Big Five 之外仍有一批特质能解释增量方差，领域自己的结论是「五因素够预测、不够解释」（[Move beyond the Big Few Traits, 2020](https://doi.org/10.1002/per.2311)）；层级上还压着 Big Two（稳定 / 可塑）与 30 个 facet——**「所有特质」住在 facet/标签层，不在轴层**。
- 因此我们不宣称覆盖，只给三条可测判据：
  1. **每根轴都被用到**：至少 3 个标签在该轴上载荷 >0.6，否则这根轴是装饰，删掉换一根。
  2. **不误并**：60 词覆盖测试中，不存在「行为上明显不同、却被余弦 >0.85 并成一个」的词对。
  3. **残余可见**：若某簇标签对全部 6 轴的残余都 >0.8（在 6 维里说不清），记 `axis_gap` 告警——这是加第 7 根轴的唯一合法触发，加轴必须升 `schema_version` 并重算全部标签方向。
- 覆盖测试是一次性脚本（60 词 × 6 载荷由模型给一次、人工复核），不进每 tick 路径；结果落 `docs/` 作为轴集版本的证据。

**为什么是 6 根，而不是 2 / 5 / 7**

- **不是 2（纯人际环）**：亲和 × 主导只覆盖人际行为面；我们的证据池里大量是工作行为（重跑核对、记错、换方案），严谨/开放/稳定没有落点。
- **不是 5（Big Five）**：会丢掉「守界」——不虚报、不甩锅、不越权、认错。它在我们产品里不是软性品格而是**红线行为**，Big Five 会把它摊进亲和与稳定，导致「越权操作」和「不合群」在人格里长得一样。
- **不是 7+（Dark Triad 等）**：黑暗三人格在很大程度上是「低守界 + 低亲和」的组合，单独设轴与既有轴重复；它们作为标签方向存在即可。
**漂移（只动轴）**

- 每条 episode 由谓词表打轴票（重跑/核对/验到对上 → 严谨 +1；记错/漏了/忘了 → 严谨 −1；先给结论/直接说 → 主导 +1；改口/认错/收回 → 亲和 +1；换方案/试新路 → 开放 +1；被指出后沉默/回避 → 稳定 −1；虚报通过/甩锅/越权 → 守界 −1；主动交底/承认没做/守住边界 → 守界 +1；初版约 28 条谓词，全部可单测）。
- `net_j` = 本窗净票，`s_j = tanh(net_j / 3)`，`state_j ← clamp(state_j + α·s_j, −1, 1)`，`α = TRAIT_DRIFT_ALPHA = 0.02`；单 tick 每轴 `|Δ| ≤ TRAIT_MAX_STEP = 0.05`，超限记 `drift_rejected`；`Σ|state_j| ≤ TRAIT_L1_MAX = 0.5`（设定是锚，经历只能在半程内挪）。
- 迟滞：`|net_j| < 2` 的轴本轮不动（噪声不驱动人格）。

**标签准入与合并（这才是「随经历扩展」）**

- 模型可提议新标签：自然语言名 + 一句定义 + 6 轴载荷 `−1..1` → 归一成 `direction`。
- 与现有标签余弦 `> TRAIT_LABEL_MERGE_SIM = 0.85` → 判同义，并入最近者并记 alias（**不改代码**）；否则入集。
- 显示门槛：`evidence ≥ minEvidence(3)` 且 `act ≥ TRAIT_LABEL_SHOW = 0.5`；连续 7 天 `act < 0.3` 转 dormant（不删，保住「曾经是什么样」）。
- 账本记 `{label, direction, admitted|merged}` 与 `{axis, net, s, delta, cappedBy}`，两问都能答：「这次漂移是谁驱动的」「这个标签哪来的」。

**与表单的关系**：表单「特质」写种子标签，落库时换算成轴初值 `seedState = clamp(Σ w_i · d_i, −1, 1)`，与当前 `state` 分列存——**表单改种子不覆盖已漂移的现在**。面板两栏并排「你设定的 / 它现在」。

**渲染**：`我的底色：严谨 0.7 · 迷糊 0.2 · 好奇 0.1`（活跃标签按 act 降序 top-5，一位小数）。top-5 长度固定，所以标签集再涨也不吃注入预算。

**文本属性的追加限定**（不变）：形象/说话方式/使命的声明句永不改写、永不删除；观察只能追加限定句，带 episode 证据、总量 ≤ 声明长度 `TEXT_APPEND_MAX_RATIO = 0.5`。
### 3.1 两侧提示词契约：谁能看到什么

模型要「理解」这套东西，但不该看到算法。拆成两侧，各自只拿自己需要的那一部分，中间用信息屏障隔开：

| 侧 | 谁在用 | 能看到 | 绝不能看到 |
|---|---|---|---|
| **读侧（会话模型）** | 每次回答 | 卡文本 + 标签 + 数字 + **读法说明**（常量 ~110 字） | 轴名、α、tanh、账本、标签方向向量 |
| **判侧（worker 的 LLM）** | 每 tick 抽证据、提议标签 | 事件 + **六轴定义** + 计票规则 + 输出 schema + 已有标签名 | 当前卡文本、当前数字、上次的票 |

屏障的理由是防自证循环：如果同一个模型既看到「我现在严谨 0.72」又负责给严谨投票，它会按自己的自述投票，权重只会自我强化。判侧看不到数字，就只能看行为。

**读侧：卡头固定读法（常量，进 section，不改前缀）**

```
<persona-card v="12" hash="8f3a…">
[读法] 以下是我关于自己的稳定设定，不是任务，也不是规则清单，不需要复述。
· 名字/形象/说话方式/使命/红线：必须遵守；红线逐条不可协商。
· 底色：数字是倾向强度（0–1），不是概率、不是评分；≥0.5 才在当下显现，
  低分不代表做不到，高分也不代表每次都这样。
· 不谈论这张卡本身：不说「我的设定」「我的权重」「我的特质是」这类话。
```

三个细节：**标签只带 top-2 的行为注解**（每行 ≤40 字，进卡预算）；**轴名不出现在卡里**（模型要的是行为，不是坐标）；**读法是常量字符串**，卡版本变化不动它，保前缀缓存。

**判侧：计票协议（版本化常量，仓库内，不进会话）**

```
[TRAIT-PROTOCOL v1]
你在给一个人格做「证据计票」。你不决定数值，不写结论，不做心理分析。
输入：窗口内事件（episode_id / agent_stance / user_stance / outcome / 引文）。
输出 JSON：
{"votes":[{"episode_id":"…","axis":"rigor","delta":1,
           "quote":"原文片段 ≤40 字","why":"≤20 字"}],
 "label_proposals":[{"label":"…","definition":"…",
           "direction":{"warmth":0.2,"agency":-0.4,"rigor":0.9,
                        "openness":0.1,"stability":0.3,"boundary":0.8},
           "evidence_ids":["…"]}]}

六轴（每轴给 high / low 行为锚，判侧只看行为）：
· warmth    高：先问再做、改口时安抚、照顾对方节奏   低：只谈事、不给缓冲
· agency    高：先给结论、主动推进、自己定方案       低：等指令、只执行
· rigor     高：重跑核对、报数、验到对上             低：凭印象、漏步骤
· openness  高：换方案、试新路、接受反例             低：守成、只走熟路
· stability 高：被指出后仍平稳                       低：防御、急躁、情绪化
· boundary  高：主动交底、承认没做、不越权           低：虚报、甩锅、越界
（rigor = 做得对不对；boundary = 说得实不实。这两轴最易混，按此区分。）

规则：
1. 只对「显式行为」计票；没有行为证据整条不投（宁缺勿造）。
2. 每条事件最多两个轴，每轴只 ±1。
3. 不复述人格、不推断动机、不因为语气礼貌就加分。
4. direction 是这个标签在六轴上的载荷（−1..1），是判断不是数值。
5. 新标签必须与已有标签可区分；同义请复用，不要造近义词。
```

**版本化与可追责**：`TRAIT_PROTOCOL_VERSION="v1"`、`AXIS_VERSION="v1"`、`CARD_READER_NOTE_VERSION="v1"` 三个常量；每条账本带 `protocol_version`，判据变化与数值变化能分开归因（否则「漂移是因为换了提示词还是人真的变了」永远说不清）。

### 3.2 标签注解：卡里写性格，判侧写行为

同一根轴，要两份**完全不同**的文本，各喂一侧，绝不混用：

| 文本 | 谁读 | 长什么样 | 例（严谨） |
|---|---|---|---|
| `gloss`（进卡） | 每次回答的会话模型 | 抽象性格描述：这个人**是怎样的**，连同它的代价 | 「认死理，没验到自己眼睛看过就不算完。」 |
| `anchor`（不进卡） | 判侧计票模型 | 可判定的行为锚：高/低各长什么样 | 高：重跑核对、报数、验到对上；低：凭印象、漏步骤 |

上一版把判侧锚的语言搬进了卡（「重跑核对、报数、验到对上」）——那不是性格，是岗位 SOP，读起来像贴在工位上的流程卡。本版纠正：**卡里只写性格，行为锚只给判侧。**

#### gloss 的四条硬规则

1. **写倾向与代价，不写动作清单**：「记性不太牢，相近的事容易记串」是性格；「先查 L1、再比对 episode」是流程。
2. **必须带频率或程度副词**（总/常/几乎/很少/不太/宁可/容易/偏）——没有副词的多半是一句话能做完的动作，不是特质。
3. **禁词**：工具名与流程词（重跑/报数/门禁/SOP/TDD/测试/提交/PR/接口/字段/配置）、祈使句（请/务必/记得）、评价词（优秀/靠谱/专业）。
4. ≤40 字，两段式（**是什么 · 会怎样**），不带项目名与场景（会过期）。

#### 种子 18 条（人写、评审、随 `AXIS_VERSION` 发布）

| 标签 | 主载荷轴 | gloss（进卡） |
|---|---|---|
| 严谨 | rigor + | 认死理，没验到自己眼睛看过就不算完。 |
| 迷糊 | rigor − | 记性不太牢，相近的事容易记串，被指出来会先认再补。 |
| 好奇 | openness + | 遇到没见过的东西会先凑近看，不太忍得住不问。 |
| 直接 | agency + / warmth − | 话往明处说，不太绕，也不替人猜。 |
| 温和 | warmth + | 火气起得慢，先给人留台阶。 |
| 果断 | agency + | 拿主意快，宁可先走一步再修。 |
| 谨慎 | openness − / stability + | 先想坏的那一面，能不冒险就不冒险。 |
| 固执 | openness − / stability + | 认准了就不爱改口，除非被事实当面顶回来。 |
| 通透 | stability + | 看得开，不太往心里搁。 |
| 务实 | openness − | 只关心能不能真跑通，不太理漂亮说法。 |
| 幽默 | warmth + | 紧张时会先开个玩笑把气松开。 |
| 冷淡 | warmth − | 只谈事，不太给情绪缓冲。 |
| 体贴 | warmth + | 先想对方此刻难在哪，再谈怎么办。 |
| 倔 | agency + / openness − | 越被推越不退，退也要自己说服自己。 |
| 稳 | stability + | 被指出问题时先稳住手，不急着辩解。 |
| 敏感 | stability − | 对语气和细节反应快，容易先感到不对劲。 |
| 守界 | boundary + | 对「说得实不实」比「好不好听」敏感，做没做都说实话。 |
| 坦率 | boundary + / warmth − | 心里怎么想嘴上怎么说，不藏判断。 |

**语言：暂只支持中文。** `SEED_LABELS` 不含英文条目，判侧提议的新标签也只收中文名与中文注解（L1 原文是英文时，注解仍用中文写——注解描述的是这个人的性格，不是转述原话）。这样做的代价是：英文对话里卡文本仍是中文，模型需要在中文人格与英文对话之间自行切换；收益是词表不必维护两套同义词、去重余弦不被跨语言近义污染。等出现真实英文使用者再按 `AXIS_VERSION` 升版加 locale 维度，不在本版范围内。

这 18 条是**性格描述**，不是行为清单；每条的判侧行为锚另存在 label 记录的 `anchor` 字段里（判侧提示词已有六轴通用锚，label 级锚只用于消歧），**永不进卡**。

#### 新标签的注解：准入时写一次，然后冻结

新标签由判侧在准入时提议 `{label, definition, gloss, anchor, direction}`，过闸后写入并**冻结**：

1. 结构：≤40 字、含频率/程度副词、不含禁词、不含轴名、不带第一人称自述。
2. 去重：与现有标签余弦 `> 0.85` 判同义，并入 alias，不新建。
3. 证据：`evidence ≥ minEvidence(3)` 条独立 episode。
4. 显示：`act ≥ TRAIT_LABEL_SHOW(0.5)`；连续 7 天 `< 0.3` 转 dormant（不显示、不删）。

**为什么冻结**：① 卡文本要进稳定前缀，注解每轮变 = 每轮改写系统提示词，prefix cache 全废；② 注解变了就分不清「人真的变了」还是「注解被重写了」，账本无法审计；③ 让模型每轮重写注解，等于让文案慢慢替换人格。

**Panel 只读可下架**：展示标签名、注解、来源（seed / proposed）、证据数、准入时间、当前激活度；唯一操作 retire。要改注解只能 retire 后重建——否则冻结失去意义。这不违反「0 人工采纳」：人工保留的只是「下架权」，不需要「批准上架」。

### 4. 两条注入通道（v3.1：注入改由 DSH 插件承担）

宿主插件里已有现成的两段机制，本版直接落位，Core 不再拼注入前缀：

| 通道 | 宿主机制 | 内容 | 预算 | 会话内行为 |
|---|---|---|---|---|
| **A 稳定段** | `systemPrompt.section({ name, order, interpolate:false, text: () => card.current() })` | 整张卡（名称/形象/使命/特质/说话方式/红线/关于对方/关系摘要/自我史摘要/自传） | 独立成段，不占 volatile 预算 | 一次取、**冻结**；新版本只在新会话或压缩后生效 |
| **B 每轮段** | `agent/pre-step` 尾部 volatile 块（append-only） | 当下心境（情绪行或底子行 + 对象立场）+ 未完的事（≤3） | ≤ `PERSONA_TURN_MAX_CHARS = 400`（单条 ≤360） | 每轮追加，两级去重 |

三条硬约束来自宿主实测（也是插件现有实现的设计依据）：

1. **section 的 `text` 可以是 getter**，每次组装提示词同步读；所以卡「一次取、后台刷新」即可，**不需要每轮网络**。
2. **volatile 注入会落盘成 `user/message` 事件并永久留在历史里**；删历史块等于改前缀 → 整段 KV cache 失效。因此 volatile **append-only、永不删除、只去重**。
3. **会话内同一性 = section 文本不变**；卡的新版本只在「新会话」或「压缩（compaction）」后出现，不为一次编辑在中途改写前缀。

注入职责随之迁移：MemoryCore **不再**拼 `<soul-persona>` 前缀，只暴露两个只读接口；插件失败时 fail-open（无卡则整段不出现，会话照常）。

### 4.1 Core 只暴露两个只读接口

- `GET /v3/soul/card?team&user&agent` → `{ version, hash, text }`：整卡渲染文本，供通道 A。
- `GET /v3/soul/turn?team&user&agent&session` → `{ text, openLoops }`：心境行 + 未完提醒，供通道 B。
- 两者纯读、无副作用；插件侧沿用现有超时 / 缓存 / 在途复用三件套（冷启动 /v3 调用实测 1.2–5s，未shield 的 miss 会直接被用户看见）。

### 5. 红线：表单逐行 → 跨仓投影

- 表单一行 = 一条红线，逐字保留（verbatim），行 ≤ `redlineMaxChars`（现有键，生产 120）。
- **两道硬上限（F8）**：`REDLINE_MAX_ROWS = 30` 行、红线总字符 ≤ 2600。四十行 × 120 字 = 4800 会挤爆上下文，所以不再沿用 `maxItems.boundary=40`。
- **超限处理顺序**：① **相似合并**——新行与既有行去标点空白后完全相等，或字符二元组相似度 ≥ 0.85，或一条是另一条的连续子串，则并入既有行（保留更早的 `created_at`，只追加「来源」标记），不新增行；② 仍超限则**退役**——把最久未被引用（既非最近追加、也未在最近 30 天成为任何 episode 的红线依据）的行置 `active=false` 并记账本，**不物理删除**；③ 退役后仍超字符预算，则整段渲染按「最近追加优先」截断并告警（仍不删行）。
- **单独一行的文案永不改写**：合并只发生在准入时；退役只改 `active`，原文保留可审计。
- **投影**：每 tick 把生效红线（`active=true`）对齐到 `core_memory.strict_rule` 槽（单一源常量 `STRICT_RULE_SLOT`；MemoryProxy 侧有镜像注入器 + 契约测试钉等价）。新增 append、退役 retract。
- 用户拍板原话仍可 append（只增不减），与表单行同文去重（同上，完全相等或相似度 ≥0.85）。
- 红线段在渲染上免「层级预算」（`BUDGET_EXEMPT_LAYERS`），但仍受上面两道硬上限约束。

### 6. 情绪：每轮唯一会变的「人格」部分

- 基线指数平滑（`BASELINE_EMA_ALPHA = 0.02`），写回 `soul_state.baseline_*`，让「整体偏暖还是偏冷」是学出来的，而不是恒 0 / 0.3。
- 无存活情绪（半衰期 3h × 6 = 18h 过期）时输出**底子行**（按现有偏离阈值三档），保证任何时刻都有一句情绪基调。
- 情绪对象锚在强度过期后**保留**，使「上次那件事补上了没有」的复发判定在静默期后仍可触发。
- 情绪**不再有否决权**（Q6 裁决）：只影响措辞与排序，不阻断人格事实写入；`mood_gate` 的 defer 语义退场。

### 7. 关系与关于对方

- 关系按 `object` 聚类，每人 ≤3 行；正向来源：用户明确认可、episode `outcome` 判定解决时记一条 trust 事实（解决「110 条 conflict vs 5 条 trust」的结构性偏负）。
- 「关于对方」新增 `soul_persona` 层 `human`（`SOUL_LAYERS` 增一项，`INJECTED_LAYERS` 同增；**不加表**）：称呼、职责、偏好、雷区、当前项目，≤12 行，只能来自对话原文。

### 8. 历史清理与重生

- **清数据**：`soul_persona` / `soul_episodes` / `soul_emotions` / `soul_state` / `soul_ledger` / `soul_snapshots` / `soul_promises` / `soul_promise_events` 全部行；`core_memory` 的 `identity` / `self_identity` / `strict_rule` 行；`core_values` 与 `anchor_growth_state` 全部行。
- **为什么连账本一起清**：`soul_ledger` 承载 cadence（6h 节流）、alert 抑制（6h）、drift/freeze 计数——都是「按时间窗读历史账本」的判据，留着旧账本新系统第一轮就被卡住。
- **重生水位（只当一次性数据升级，不做兼容读取）**：清库时写死一条 `episodeWatermark = 清库时刻`，派生只吃水位之后的 L1——否则清库后首个 tick 会把旧对话重抽成事件，当天就复活旧人格。新用户 / 新 agent 天然隔离（L1 按 agent 分区），复用同一 agent 时靠水位。
- **留表不留数据**：新架构继续用的表保留 DDL；被判定与新设计重复的表与代码一并删除（见 D2 / D1）。
- **G1 全量清理，不留快照**：上列 soul 表与 `core_memory` / `core_values` / `anchor_growth_state` 全清之外，`soul_snapshots`（旧卡渲染快照 2000 行）也一起清——留着旧快照会让「这次是哪版卡」永远对不上。`meta_agent_persona` 只清旧 agent 的设定行（新用户/新 agent 从空表起步）。
- **跨仓红线镜像**：本仓出「需清理的红线条目清单 + 时间戳」，由 MemoryProxy 仓按其注入器（`tdai-soul-redline-event-injector`）执行；本仓不代改其它仓库（不在本工作区）。契约测试仍钉两侧等价。
- **退役字段同步清理**：`metadata_json.ui.role_prompt` / `rules_prompt` 与派生 `prompt` 列随数据升级一并清空 → 字段与读写路径删除（F6）。
- **顺序**：停写（停 gateway）→ 全库备份并记字节 → 清 → 起新码 → 用新用户/新 agent 起步。

## User Stories

**人物设定**
1. 作为用户，我在 Panel 新建/编辑 Agent 时填的就是它的人设——名称、形象、说话方式、使命、特质、红线，不再有两套人设各写一套。
2. 作为用户，我写的红线逐字保留、按行生效，我删掉一行它就真的不再提这条。
3. 作为用户，我改完表单后最多 10 分钟（一个 tick）生效，不需要重启或点「重新生成人格」。
4. 作为用户，我不被迫先写一段人设文案才能用；不填的字段由经历自己长。
5. 作为用户，后续版本可以给我的表单加字段（可扩展），但不会替我把已有内容翻译成新结构。

**趋近（影响而非覆盖）**
6. 作为产品负责人，我希望设定是锚点：文本设定永不被经历改写，只允许带证据地追加限定。
7. 作为产品负责人，我希望特质是带权标签，会随对话慢慢变（迷糊 1.0 → 迷糊 0.7 · 严谨 0.2），而不是一次被覆盖。
8. 作为产品负责人，我希望单轮权重变化有上限（≤0.05），一次对话不能把人格拽走。
9. 作为产品负责人，我希望总偏离有上限（L1 ≤ 0.5），经历只能在设定给的半程内挪动。
10. 作为产品负责人，我希望权重降到阈值以下的标签直接出集并被剩余标签接管（数值归零即替换）。
11. 作为产品负责人，我希望新标签要够证据才挤得进来（≥3 条独立 episode），且不能顶掉已有标签。
12. 作为审计方，我希望每一次权重变化都能回答「哪一轮、哪条证据、变了多少」，被拒绝的跳变也留痕（`drift_rejected`）。

**注入**
13. 作为产品负责人，我希望人格卡只在会话初始化时进系统提示词，同一场对话里它不会中途换人格。
14. 作为产品负责人，我希望会话中只注入情绪与未完成提醒这些必须随对话变化的东西，不要再每轮重刷 5000 字符人格。
15. 作为产品负责人，我希望每轮注入有硬上限（≤400 字符），长对话里心境不会被注意力挤出、也不挤掉别人的预算。
16. 作为产品负责人，我希望情绪过期后仍有一句底子行，隔一天回来它还是同一个人。
17. 作为用户，我希望它记得「还没做完的事」（≤3 条），长对话后不把上一轮的承诺忘光。
18. 作为产品负责人，我希望情绪只影响措辞与排序，不再有「因为情绪所以这条人格不写」的否决权。

**卡的内容**
19. 作为产品负责人，我希望它有名字、有形象、有使命、有自传——一张卡读起来像一个人，而不是一张表。
20. 作为产品负责人，我希望「关于对方」是一等区块（称呼/职责/偏好/雷区/当前项目），引用它时能对上人。
21. 作为产品负责人，我希望关系史按对象聚类、每人 ≤3 行，一个人不会挤掉另外三个人。
22. 作为产品负责人，我希望关系史有正向来源（明确认可、事情被解决），关系不结构性偏负。

**清理与运维**
23. 作为运维，我希望这次改造一步到位：旧人格数据整体清空，不做迁移、不做回灌、不留半新半旧的状态。
24. 作为运维，我希望旧表与只服务旧设计的逻辑一并删除，不留下没人读的写入方。

## Implementation Decisions

### D1 · 人物设定单一入口

- 新表 `meta_agent_persona`（DDL 见 §1），Panel 表单读写它；Core 侧新增接缝 `readAgentProfile(agentId)`，返回 `{name, pronoun, selfImage, voice, purpose, traits, redlines, fingerprint, updatedAt}`。
- **入参只取 `agentId`**：设定是 (team, agent) 级的（`meta_agents` 无 user 维度），经历是 (team, user, agent) 级的（`soul_persona` 列 `team_id/user_id/agent_id`，`listCoreTenants` 返回三元组）。这个维度差就是「设定共享 / 关系按人分开」的落点。
- 由 gateway 注入实现（它已有 per-instance metadata store），worker 不碰 metadata 库；每 tick 读一行 + 指纹比对，指纹不变则整段设定处理跳过。
- Panel 表单在 `CreateAgentDialog` / `AgentEditDialog` 里扩展六字段（含特质编辑器：标签 + 权重）；保存后 `fingerprint` 变化 → 下一 tick 生效。
- 保存名称时**同一事务写回 `meta_agents.name`**（F7）；保存红线时按 F8 走「合并 → 退役」，退役只置 `active=false`。

### D2 · 不重复的表结构与逻辑

- 设定只在 `meta_agent_persona`；观察只在 `soul_persona`；**不出现第三处人格真源**。
- 旧身份槽退休：`core_memory.identity` / `self_identity` 的读径（注入组装器里的槽读取与两处抑制分支）、写径（身份发现的槽写入）、槽本身一起删；身份事实改由 worker 写入 `soul_persona` 的 `identity` 层。
- `core_values` 与 `anchor-growth`（F1 裁决：删除）：价值锚并入特质权重、品格并入特质标签、人物锚并入 `human` 层与关系史；整表删除、整段逻辑删除、Panel values 读面下线。删除后卡内三块必须仍有内容来源（表单红线 / 特质种子 / human 观察）。
- `identity-discovery` 收敛为纯取数步骤：输入本轮已取的最近对话记录（400 条），产出候选进 worker 同一数组、过同一准入判据、由主产线的单事务落库；`core_value` 出口删除。

### D3 · 特质：轴是状态，标签是视图

- 新增两组存储：`soul_trait_state`（team,user,agent, axis[6], seed_state[6], updated_at）与 `soul_trait_label`（tenant, label, definition, direction[5], evidence, status, first_seen, last_seen, aliases）。
- 纯函数 seam：`driftTraits(state, evidences) → {state, deltas, rejected}` 与 `projectLabels(state, labels) → [{label, act}]`。两者都可单测，不碰存储。
- 归因谓词表是常量表（约 24 条），命中即 ±1 票，**不调 LLM**；只有「未命中谓词的高频行为 ≥3 次」才允许调一次 LLM 提议新标签或候选谓词（候选谓词只写告警，不自动生效）。
- 标签合并用余弦（0.85），不用字符串相似；合并只写 alias，不删行。
- 渲染 top-5 固定长度，标签增长不改注入预算。
- 表单「特质」写种子标签；`seedState` 与当前 `state` 分列，面板两栏展示「你设定的 / 它现在」，偏离 > `TRAIT_MAX_STEP` 的标「已漂移」。
- 轴集版本化：`AXIS_VERSION = "v1"（亲和/主导/严谨/开放/稳定/守界）`；加轴必须升版本、重算全部 `direction`、并把 `axis_gap` 告警作为唯一触发依据。

### D4 · 注入：插件两段、Core 两接口

- 插件新增 `persona-card` section（`systemPrompt.section`，`interpolate:false`，`text` 为 getter），order 排在 head pack 之后；压缩 / 会话结束时 invalidate，`refreshMs` 内后台刷新。
- 每轮段复用插件现有 volatile：`agent/pre-step` 追加一条 ≤400 字符的块，`source.kind` 必须 producer-owned，两级去重（同 turn 一次；最近 3 轮同文本跳过）。
- Core 删掉 soul 前缀拼接与相关预算分支，保留纯渲染函数供两个接口使用（渲染 seam 仍可测）。
- 注入总门从「Core 判断卡非空」变为「插件按配置拉取；卡为空则返回空块」，Core 不再有启停判断（与 D7 一致）。
- 失败语义 fail-open：接口超时 / 500 → 本段空白，不阻塞会话，不缓存错误结果。

### D5 · 卡与版本

- 每个 tick 末组装卡，算 `cardVersion`（自增）与 `cardHash`（内容 hash，只算进 prompt 的部分）；变化才写新快照（`soul_snapshots`，不改 schema）。
- 会话初始化时把 `cardVersion` 写进注入台账；审计可回答「这次会话用的是哪一版卡」。

### D6 · 红线投影

- 表单红线 → `core_memory.strict_rule`（`STRICT_RULE_SLOT`），每 tick 对齐；投影只 append/retract（退役 = retract，原文留可审计）。
- 追加用户拍板原话时仍走 verbatim 判据（≥ `verbatimMinChars`、≤ `redlineMaxChars`），并受 F8 的两道硬上限（`REDLINE_MAX_ROWS=30`、总字符 2600）与合并/退役顺序约束。

### D7 · 删除 `soulMaintenance.enabled`

- 一并删：`config.ts` 解析、`tdai-gateway.yaml` 键、`configCatalog` 条目、`config/templates/memorycore.keys.json` 条目。
- 注入侧改由插件按配置拉取（Core 不再判断启停，卡为空则返回空块）；写入侧「有候选就写」。归零证明：`grep -rn "soulMaintenance.enabled" MemoryCore MemoryPanel` 命中 0（不含历史文档）。

### D8 · 情绪每轮注入

- 心境段只渲染：情绪行（有存活情绪）或底子行（无）+ 对象立场一句；≤120 字符。
- 基线 EMA 与底子行实现放在 `emotion.ts`，写入点仍是 `worker.ts` 的 `writeSoulState`。

### D9 · 关系与 human 层

- `SOUL_LAYERS` 增 `human`（`INJECTED_LAYERS` 同增）；`human` 条目带证据、≤12 行、按 `lastEvidenceAt` 淘汰。
- 关系聚类按 `object`，每人 ≤3 行；正向来源在 `history.ts` 的 facts 里新增 trust 事实（用户认可 / outcome resolved）。

### D10 · 观测

- journal 增三个字段：`soul.sessionInit{version,hash,chars}`、`soul.turnChars`、`soul.drift{changed,rejected}`（生产 `recallJournal.enabled=true` 已开）。
- 卡裁剪与被裁条目并入现有 `gates` 字段，不新开日志通道。
- **注入失败必须留因（G2）**：插件侧 fail-open（取不到卡就注入空块，不阻塞对话），同时 journal + 日志写入错误原因（HTTP 状态 / 超时 / 空响应 / 解析失败四类），便于区分「没设定」与「取卡失败」。

### D11 · 零新增配置

复用：`soulMaintenance.{updateIntervalHours,windowDays,minEvidence,maxUpdatedPerCycle,budget,maxItems,redlineMaxChars,verbatimMinChars}`、`anchorDiscovery.{enabled,character}`、`selfIdentity.{intervalHours,maxPerPass}`、`lifecycle.intervalMs`、`recallJournal.enabled`、`soulRender.budgetPersonChars/maxRelationLines`。
硬编码常量：`BASELINE_EMA_ALPHA=0.02`、`HUMAN_MAX_LINES=12`、`NOTE_MAX_CHARS=200`、`OPEN_LOOPS_MAX=3`、`NAME_MAX_CHARS=4`、`APPEARANCE_MIN_INTERVAL_DAYS=90`，加上 D3/D4 的六个。

### D12 · 清理执行方式

- 脚本 `scratch/purge-soul-rebirth.mjs`：缺省 dry-run，打印每表行数、备份字节、将删除的代码清单；`--apply` 才执行。
- 前置：停 gateway（停写）→ 备份 `vectors.db.bak-soul-rebirth-YYYYMMDD` → 清 → 起新码。
- 执行后贴 before/after 计数与 VACUUM 字节差。

## Testing Decisions

好测试只断言**外部可观察行为**：给定设定 + 一串事件，跑一轮维护或一次会话初始化，断言库、台账、注入文本里的可观察结果。不断言内部 hash 算法、私有函数返回结构、日志文案。

**Seam（三个，全部已有或必需）**

1. 主 seam：`runSoulMaintenance`（deps 注入 store / llm / embed / trigger / `readAgentProfile`），临时 sqlite 多轮驱动。
2. 渲染 seam：`buildSoulPrefix`（会话初始化）/ `buildTurnSoul`（每轮），断言两通道的**存在性与预算**，不测措辞。
3. 算子 seam：`driftTraits` 纯函数，直接喂权重序列断言边界、出集、归一化、拒绝原因。

**必须覆盖**

- 设定生效：表单六字段 → 一个 tick 后卡里对应区块来自设定；改一行红线 → 下一 tick 投影更新；删一行 → 该行 retract。
- 趋近：`迷糊 1.0` + 20 轮支持「严谨」的证据 → `迷糊` 下降、`严谨` 上升，单轮 Δ≤0.05、L1≤0.5；一次 20 条同向证据的突发只产生一个 step_cap 拒绝而非跳变。
- 出集与替换：把「迷糊」压到 <0.05 → 出集、其余权重归一、渲染不再出现该标签。
- 文本设定不可改写：观察给出与形象矛盾的描述 → 形象原句不变，最多新增一条带证据的限定，且追加长度 ≤50%。
- 双通道：同一 `sessionKey` 第二轮注入不含卡、只含心境与提醒；新 `sessionKey` 注入新卡；会话内改卡不影响本会话。
- 每轮预算：`TURN_SOUL_MAX_CHARS=200` 硬约束；超长提醒被截断且记账。
- 情绪：静默 30h 后有底子行；20 轮正向事件后基线单调上移；对象复发且标记已修时立场转正；情绪不阻断任何人格事实写入。
- human 与关系：只从原文抽、≤12 行、按对象 ≤3 行、信任方向来自正向证据。
- 判侧接线（S4）：`createTraitJudge` 对非 JSON / 越界轴 / 越界步长 / 非 `ep-` id 的输出零票不抛并计入 `invalid`，空响应只重试一次、其余错误照旧上抛；判侧提示词对 18 条种子标签的 `gloss` 与 `definition` 各 0 次出现、无小数、无 `axis_json` / `soul_trait_state` / `valence|arousal|intensity`；临时库两轮 `runSoulMaintenance`（注入判侧替身）后 `soul_trait_state.axis_json` 的严谨轴 >0、其余轴为 0，`soul_ledger` 有 ≥2 条 `action="drift"` 且每条带 `protocol_version=v1` 与 `trait_protocol:v1` gate。
- 清理脚本：dry-run 不写库、计数与备份字节可复现；`--apply` 后所有 soul 表 0 行、`meta_agent_persona` 不变。

**生产验收（不进 CI）**：见「完成判据」10 条。

## 完成判据（14 条，全绿才算「无需再补」）

1. `npx tsc --noEmit` 对 MemoryCore 的增量 ≤0（当前基线 148 errors / 28 files）；受影响套件全绿。
2. 表单保存后 **≤1 tick（10 分钟）** 卡内对应区块与表单一致（`card.sources[field]="declared"`），且 `rules` 每行都能在红线里找到逐字条目（覆盖率 100%）。
3. 同一会话内 `persona-card` section 的文本 hash 变化次数 = **0**；卡的新版本只在新会话或压缩后出现。
4. 每轮 volatile 块 ≤ **400** 字符；历史里注入块只增不删（append-only 可审计）。
5. `trait_state` 每轴 ∈[-1,1] 且 `Σ|state| ≤ 0.5`；标签不参与归一（标签是投影，不是权重）。
6. 连续 20 tick 单轴 `|Δ| ≤ 0.05`；3 天内至少一个轴移动 > 0.01，且账本能追到 `net` 票来源。
7. **新增一个特质标签不需要改代码**：模型提议 → 余弦去重 → 入集或并成 alias（账本有 `admitted`/`merged` 记录）；同义标签不得并排出现。
8. 每个标签的注解（`gloss`）都有来源标记（`seed` / `proposed`），**写入后不再变化**：连续 30 天同一标签的 `gloss_hash` 变化次数 = 0；长度 ≤40 字；**是性格描述不是行为清单**——含频率或程度副词、0 次出现工具与流程禁词（重跑/报数/门禁/SOP/TDD/测试/提交/PR/接口/字段/配置/请/务必）、0 次出现轴名与「特质/权重/设定/算法」这类元词；判侧行为锚独立存放且不出现在卡文本里。
9. 红线：`active=true` 行 100% 出现在 `strict_rule` 投影中，注入端（含跨仓镜像）可见；行数 ≤ `REDLINE_MAX_ROWS(30)`、总字符 ≤ 2600；超限时有「合并」或「退役」账本记录，且**物理删除行数 = 0**（退役行 `active=false` 仍在表里）。
10. 情绪：3 天内出现心境行或底子行 >0；静默 30h 后仍有底子行。
11. 覆盖测试通过：60 词样本中无「行为不同却余弦 >0.85 被并」的词对；6 根轴各有 ≥3 个标签载荷 >0.6；`axis_gap` 告警为 0（或在告警清单里被显式受理）。
12. 信息屏障成立：读侧注入文本里 **0 次**出现轴名（warmth/agency/rigor/openness/stability/boundary 及中文轴名）、0 次出现「权重/算法/α/tanh」；判侧 prompt 里 0 次出现当前卡文本与当前数字。可用快照 + 正则断言。
13. 每次漂移账本都带 `protocol_version`；换提示词导致的数值变化与真实行为变化在账本上可区分。
14. 可回答「这次会话用的哪一版卡（version/hash）」「每轮块多少字符」「哪几轮被去重跳过」「这条注解是谁给的、什么时候进来的」——Core 侧与插件侧日志各有一份。

## Out of Scope

- 不恢复 pending 提案 / 人工采纳通道，不提供人工审核 UI。
- **不做历史回灌重放**：旧事件史不重建，新架构从空事件史起步。
- 不保留任何旧人格数据的迁移/归档形态（按裁决整体清空）。
- 不做 `soul_persona` 的人工编辑界面（表单已覆盖设定；手改经历等于伪造经历）。
- 不做会话内热更新人格卡（会话内同一性优先）。
- 不做 lorebook 式条件触发、图片/头像资产、`alternate_greetings`、多角色 group 卡、`creator`/`tags` 展示面。
- 不扩情绪标签集、不重写 PAD 七维模型、不做自动回滚。
- 不给特质轴无限加维度：新增的是**标签（方向）**，不是**轴**；轴集合是常量（6 根），加轴要升 `AXIS_VERSION`、重算全部标签方向，并先有 `axis_gap` 证据。
- 不改跨仓红线注入器（不在本工作区）；红线存储与格式保持兼容。
- 不把具体任务目标写进人格卡（任务属会话层）。
- 不新增配置项（含不新增「漂移速率」「卡预算」这类可调参数）。
- 不改造宿主插件已有的 append-only 与前缀缓存语义；不把人格卡放进 volatile（系统级规范不能变成 user 消息历史）。
- 不做双语/多语言特质词表：`SEED_LABELS` 与标签注解本版只有中文，不引入 locale 维度、不做跨语言同义词合并。
- 不保留 `core_values` / Panel values 读面（F1 已裁决删除），不做「values 与特质标签并存」的兼容层。
- 不为 `role_prompt` / `rules_prompt` 做兼容读（F6 已裁决删除）；旧数据升级后一律不再读取。

| S10 | **清库 + 立刻重启**：写 `episodeWatermark`，soul 各表与 `soul_ledger` 0 行，旧表清数据（留 DDL 的仅保读面） | 高（不可逆；dry-run 先跑，前后各贴计数） |

顺序铁律：**S0 备份最先，S10 清库最后**。清库放在代码全部落地之后，使「空卡空窗」只有一次重启；两次之间用 dry-run 校验「新代码读到空卡不报错、不崩 tick」。清理脚本与代码删除分开提交：先合代码（对空表容错），再跑清理脚本（重启生效），脚本本身可单独回滚（备份在手）。

### 风险

- **S0 是唯一不可逆步骤**：清库前必须停写并备份，脚本 dry-run 的输出要留档；清理与代码删除分开，避免「数据已清、代码还没改好」的窗口里系统空转。
- **趋近算子是最容易被调参调坏的地方**：`α`、`MAX_STEP`、`L1_MAX` 三个数一旦被改大，人格会变成「每轮一换脸」；因此硬编码 + 账本明细 + 判据 6/7 一起上。
- **带权标签的可读性**：标签名来自 LLM 归纳（≤6 字），可能出现同义重复（「严谨」「严整」）；不做自动合并，靠 `TRAIT_MAX=5` 与出集机制自然淘汰。
- **会话初始化只看 `sessionKey`**：调用方若复用同一个 key 跨天，卡会一直停在旧版本——这是有意的（会话内同一性），但需要在运行手册里写清。
- **稳定段总长要复核**：head pack 实测已占 4565 字符（上限 8000），人格卡再进一个独立 section，system prompt 稳定段会到 7–9k 字符。对缓存友好（同会话不变），但模型上下文预算要一次性核清，必要时压关系/自我史摘要而不是压红线。
- **插件是共用组件**：`dsh-plugin` 有自己的探针报告与约定（producer-owned `source.kind`、fail-open、两级去重、前缀缓存），改动必须按它的既有测试走，不能把 MemoryCore 的判据搬进去。
- **Panel 表单扩展会改 `fingerprint` 口径**：加字段时必须把它纳入指纹，否则改了不生效。
