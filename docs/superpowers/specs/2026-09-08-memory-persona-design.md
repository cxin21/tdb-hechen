# Persona 演进（自我模型）· 设计

> 触底：spec 支柱「身份(F1)」+「§6」+「灵魂：persona 是长出来的，不是贴上去的」。依赖 H（巩固供料）。
> 原则（承前讨论）：L3 画像不是建完即死，而是随巩固持续演化；跨会话一致，用得上"我确实喜欢 X"的真记忆。

## 1. 目标
- persona 由巩固(H)的持续态 + L2 场景**重聚合驱动**，随经验演化。
- 保留"跨会话一致"：不因一次对话就大改；重要变化进入核心画像，噪音不污染。
- 支撑 F3：用得上真记忆，而非每天重新认识。

## 2. 演化机制
- 触发：H 巩固产出新的持续态，或以 `significance/priority` 超过阈值的行为产生。
- 生成：`persona-generator` 以「旧 persona + 近期持续态」合成新画像（增量式，非整批重写）。
- 保守：默认只并入 `certainty=observed` 且有显著性支撑的结论（推断开标签，不冒充画像事实）。

## 3. 一致性保护
- 冲突：新画像与旧画像矛盾时，带 `certainty` 与时间证据裁决；无证据则保留旧 / 标"待确认"。
- 防漂移：一两次反常不重写；连续高显著性才让核心画像变（像人"不会因为一天转变是它就是变"）。

## 4. 存储
- `persona.md` 演进如常（L3），新增演化留痕段（每次改动的 reasoning + 触发持续态 ref）。

## 5. 与核心 memory(K) 关系
- 高价值且稳定的画像结论可同步进 `core_memory`（agent 可维护的"自我"）；K 读取 persona 作为基线。

## 6. 非目标
- 不做"人格分裂"多套画像；不做无约束自动发。

## 7. 待评审
- "显著才变"的阈值；合成 prompt 的一次性成本控制（用增量式控制 token）。
