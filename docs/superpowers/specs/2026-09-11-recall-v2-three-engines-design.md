## 引擎二 · PPR 全图扩散（核心，最高优先）

### E2.1 算法规格

**图构建（每次查询，租户内）**
- 节点集 = 当前租户可见的 l1_records（isolation 三元组过滤，T14 两步模式）
- 边集 = l1_links 中两端点均在节点集内的边：
  `SELECT source_id, target_id, type, strength FROM l1_links WHERE strength >= graphMinStrength(0.5) AND 两端点可见`
- 边权 = strength（0..1）；**遍历按无向**（记忆关联在召回语义上对称：A 因果→B，回忆 B 也应浮现 A）——实现：邻接表双向各记一条（同权）
- 孤立节点（无边）不进图（PPR 无意义）

**种子向量（个性化项 p）**
- 种子 = 本次检索的门槛后命中（hit 集合）
- 种子权重 = hit.score 归一化：`p_i = score_i / Σscores`（相关性越高的命中，扩散影响力越大）
- 无命中 → 无 PPR（无种子无扩散，天然退化）

**迭代**
```
r⁰ = p（种子分布起步）
r^(t+1) = d · M · r^(t) + (1-d) · p
  M：列归一化转移矩阵（无向边权/度）
  d = pprDamping（默认 0.85）
收敛：max|r^(t+1) - r^(t)| < 1e-6 或 30 次迭代
```
- 多跳自动发生：A→B→C 链上，C 以几何衰减出现在 A 的种子里（**一步计算覆盖多跳**——一跳 BFS 做不到的）

**输出评分与入池**
- 非种子节点按 PPR 分降序取前 `pprTopK`（默认 10）
- 候选分 = `maxHitScore × graphDiscount(0.6) × (pprNorm_i / maxPprNonSeed)`（pprNorm = 该节点 PPR 分 / 非种子最大值——保持折扣语义：图候选恒低于命中）
- 标注 = `[graph:ppr]` + 主导边类型（该节点入池贡献最大的边类型，取自累积扩散量）
- **T2 门 / occurred_at 业务时间列 / 租户过滤照常**（图候选同样受置信度分层与时间语义约束）

### E2.2 复杂度实证
- 生产图规模：977 节点 / 边数待测（预计 200-400）——稀疏 Map 邻接表 + 30 次迭代 × 边数 ≈ 万级运算，**微秒级**，无性能风险
- 伴随 LLM 调用：零（纯本地图计算）

### E2.3 替换决策
- R-A2 的一跳 BFS 补池逻辑**整体替换**为 PPR（一跳 = PPR 单迭代的退化情形，保留即冗余）
- R-A2 的 verify-ra2 断言相应更新（**预期行为变更，登记**：补池从一跳变多跳扩散）
- tcvdb 伴生库：PPR 跑在**伴生库的 l1_links**（T2 伴生模式，同一份图数据）——tcvdb 主存不影响图数据来源

### E2.4 失败安全
- 空图/降级/租户无边 → 零图候选（现状退化）
- PPR 计算异常 → catch + warn + 零候选（不阻塞主检索）

## 引擎一 · 查询自动扩展（LLM 语义邻域，零人工）

### E1.1 规格触发
- 每次 executeMemorySearch / auto-recall 调用（九通道检索前）
- 开关：`queryExpansion.enabled`（默认 true）/ `maxTerms 8` / `ttlMs 600000` / `timeoutMs 8000`

### E1.2 扩展调用
- LLM：standalone runner（ark-code-latest）——**maxTokens 覆写 8192**（推理模型预算教训：backfill 4096 全空）
- Prompt（零语料泄漏——纯语义扩展，不给记忆内容）：
  ```
  给出与以下检索查询语义相关的搜索词（同义词/上下位概念/相关术语），
  用于扩大文档检索的召回范围。输出 JSON 字符串数组，5-8 个，不要解释。
  查询：<query>
  ```
- 解析：JSON 字符串数组；非字符串项丢弃；**去重 + 去除与原 query 相同项**
- 缓存：`Map<query, {terms, at}>` TTL 10 分钟（E1 同款模式）；同 query TTL 内复用

### E1.3 检索合并
- **FTS 路**：扩展词以 OR 并入 FTS MATCH 表达式（`(原词) OR (词1) OR (词2)…`）——词面足迹 widening
- **向量路**：保持原 query（语义相似已处理改写；逐词 embedding = N 次外呼，不做）
- 候选并集后**照常过绝对门槛**（扩展只加候选，门槛仍裁决——宁缺毋滥不破）
- 命中标注：扩展词命中的条目不特殊标注（对用户透明，门槛保证质量）

### E1.4 失败安全
- LLM 失败/超时（8s）/解析失败 → 无扩展，原 query 照常（退化安全 + warn 一次）

## 引擎三 · 注意力自动平衡（探索位 + 结论放宽）

### E3.1 探索位
- 最终排序后：若前 N 全为高 recall_count 记忆 → 末位替换为"结构命中但 recall_count 最低"的池内候选，带 `[explore]` 标注
- 候选资格：任一结构通道命中（[graph:ppr]/[value:]/scene 命中）且 recall_count < 池内中位数
- 开关：`exploreSlot`（默认 true）

### E3.2 结论层放宽（R7 结论层的分析型触发）
- 分析型 query 检测（启发式，宁缺毋滥）：query 含分析标记（怎么/为什么/如何/分析/评估/对比/差异）且长度 > 8 字
- 命中分析型 → L2 结论层追加"significance top-5 的 durative 结论"（**无需 scene 命中**——蒸馏结论对分析问题浮出）
- 无分析标记 → 现状（scene 命中才出结论）
- 开关：`conclusionRelaxedForAnalytical`（默认 true）
- **预算约束（2026-09-12 R7 对抗审查修补 d54661e 实证登记）**：追加候选在组装前统一被
  R7 预算切分的 halfLimit 封顶（`auto-recall.ts` V2-3 块后 `slice(0, r7HalfLimit)`）——
  生产 maxResults=5 时分析型结论层实际额度 = **2 条**，"top-5 浮出"的候选生成上限不等于
  注入上限。top-5 语义保留在候选生成侧（扩池供 selectL2Conclusions 优选），注入侧以
  R7 §1 预算模型为准（总行数 ≤ maxResults，真链路断言 `auto-recall-assembly.test.ts`）。

### E3.3 强化边际（登记，不实施）
- R8 的 log 缩放已使边际递减；跨轮衰减旋钮登记为未来可选项（防自指循环的长期手段）

## 三引擎组合流水线（一次查询的完整时序）

```
query "怎么提高召回的全面性和准确性"
│
├─ 引擎一：LLM 扩展 → ["召回率 覆盖率","误差 红牌","utilization",…]
│   → FTS OR 扩展检索 + 原query 向量检索 → 绝对门槛 → 命中集 H
│
├─ 引擎二：PPR(种子=H, 图=租户 l1_links)
│   → 非种子 top-10（多跳：命中记忆的因果/演进链 2-3 跳邻居）
│   → 候选池 += 折扣分 + [graph:ppr] 标注
│
├─ 排序：九通道 tiebreak + coreRef + occurred_at 业务时间排序
│
├─ 引擎三：分析型判定 → L2 结论（significance top-5）入结论层
│         → 探索位：低频结构命中占末席 [explore]
│
└─ 注入：结论块 [结论] + 经验折叠 + 探索位——四路来源齐备
```

**对照红牌样本 query 的预期**：「怎么提高召回的全面性和准确性」——引擎一扩展词命中【红牌诊断】【利用率矩阵】记忆（文本足迹 widening）→ 引擎二把它们的图邻居（R7 设计/九通道实现记忆）跟进 → 结论层浮出 L2 蒸馏结论 → **红牌缺席问题在此 query 上被三引擎合力解决**。

## 实施顺序与验收

| 序 | 任务 | 规模 |
|---|---|---|
| 1 | 引擎二 PPR（ppr.ts 纯函数 + 两路集成 + R-A2 一跳替换） | 1 天 |
| 2 | 引擎一 查询扩展（LLM 链路 + FTS OR 合并 + 缓存） | 1 天 |
| 3 | 引擎三 探索位 + 结论放宽 | 半天 |
| 4 | golden 前后锚 + P@5/全面性对照 + 全量回归 | 半天 |

**验收**：
- verify-v2：PPR 单元（多跳扩散/收敛/空图/租户/确定性）+ 引擎一扩展断言 + 引擎三三态 + 关断矩阵（每引擎独立 0=基线逐位）
- golden 前后锚 + P@5 对照（**预期 P@5 上移**——扩展词+图扩散捞回文本不匹配的主题相关记忆）
- 全量回归 + 注入块人工目检

## 局限性声明
- 引擎一 LLM 扩展质量有方差（推理模型思考预算——8192 覆写 + 失败退化）
- 引擎二 PPR 在图稀疏期（边少）收益有限——边密度随 coreRef/关联积累增长
- P6 置信度时间衰减 / P7 双时态召回（"当时 vs 现在"）——Phase-2 roadmap，登记
