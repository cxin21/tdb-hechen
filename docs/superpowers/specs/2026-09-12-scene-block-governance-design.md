**根因**：块体治理只有 prompt 级约束，**代码层零 enforcement**——LLM 违规（超限、追加式重复）无任何拦截。

## 2. 目标 / 非目标

**目标**
1. 块体有代码级硬上限，超限必被治理（蒸馏或兜底截断），不再依赖 LLM 自觉。
2. 存量 188K 块修复到上限内，坏字符与重复句清零。
3. 选择策略显式化：超限裁剪保留什么，有第一性依据且可追溯。
4. 退化安全：治理关闭（配置缺省）时全链行为与现状逐位一致。

**非目标**
- 不改 L2 scene 的"蒸馏块"设计意图与 LLM agent 写入机制。
- 不动注入端 CAL C1 截断（它是防线末端，已实证合格）。
- 不做跨块合并策略改造（MERGE 机制维持现状）。

## 3. 方案对比（决策框架口径）

| 方案 | 说明 | 结论 |
|---|---|---|
| A. 强化 prompt 规则 | 在提取 prompt 里重申/加严上限 | ❌ **已实证被无视**：1500 字符规则在场，实际 188K；无 enforcement 的规则不是约束 |
| B. 代码级超限守卫 + LLM 蒸馏重写 | 提取批次后代码扫描块体，超限触发独立蒸馏 pass；蒸馏失败码点安全硬截断兜底 | ✅ **推荐**——改动点集中（一个治理模块 + 配置键），复用在场的 backup/restore 与 LLM 基建，符合"改动点最少、与配置层协同" |
| C. 追加式日志 + 定期归档轮换 | 块体改 append-only，历史滚动归档 | ❌ 推翻 scene 蒸馏块设计意图，改动面大，违背渐进零推翻纪律 |
| D. 仅靠注入端截断维持 | 现状 CAL C1 | ❌ 治标：块体无界增长继续污染索引、检索与 CC 指标；尾部坏字符即截断路径前科 |

**超限动作子裁决**：LLM 蒸馏重写（✅ 主案）vs 硬截断（❌ 主案——3 个 U+FFFD 即字节级截断前科；✅ 仅作蒸馏失败 fail-safe）。

## 4. 选定方案（B）细节

### 4.1 选择策略（写入蒸馏 prompt 的保留优先级）

**不可重构性优先**——保留排序：

1. **未闭合事项**（待确认/矛盾点）：L1 原文里找不到的推理状态，丢失不可逆。
2. **演变轨迹**：偏好/观念变化的浓缩，同属不可重构。
3. **时近性**：近期（滚动窗口内）决策结论。
4. 已闭合叙事：块内只留一句索引级结论，**原文降级可查 L1**（可重构，故可弃）。

依据：块体的用途是"结论层直接回答主题"；该优先级与场景模板自身章节设计（待确认/矛盾点、演变轨迹）同构，非外来发明。

### 4.2 治理流程（提取批次后，代码守卫）

```
scene-extractor 批次完成（backup 已在场）
→ 治理模块扫描 scene_blocks/*.md 块体大小（码点计数，非字节数）
→ 块体 ≤ maxBlockChars → 放行（现状路径，逐位一致）
→ 块体 > maxBlockChars → 蒸馏 pass：
   ① 独立 LLM 调用（读原块 + 选择策略 prompt）→ 产出 ≤ maxBlockChars 的蒸馏块
   ② META 保留 created，updated 刷新，summary 重写，heat 保留
   ③ 写回前 backup（复用 backup.ts 既有机制）
   ④ 产出后复扫：仍超限或含 U+FFFD → 码点安全硬截断兜底（surrogate-safe，复用
      truncateConclusionContent 同族实现）+ loud 日志（防静默降级）
→ 蒸馏 LLM 失败/超时 → 跳过本轮治理（保留原块）+ loud 日志；下轮批次再触发
```

### 4.3 存量修复

同一蒸馏 pass 一次性应用于存量超限块（`TDB团队-技术架构文档.md` 188K → ≤8K），修复后验收：≤ 上限、零 U+FFFD、抽样句重复计数 =1。

### 4.4 配置（配置化不硬编码纪律）

```yaml
sceneGovernance:
  enabled: false            # 代码缺省 false（逐位现状）；yaml 开启
  maxBlockChars: 8000       # 超限触发蒸馏（码点）
  distillTimeoutMs: 60000   # 蒸馏 LLM 超时
  hardCapChars: 20000       # 蒸馏失败兜底硬截断上限（仅 enabled=true 时生效）
```

config.ts 解析 + clamp + types.ts 声明 + yaml 注释登记；**代码缺省 enabled=false，生产行为零变化，yaml 开启才生效**。

## 6. 待测试 / 待确认 / 待完善

- **待测试**：治理模块单测（超限/不超限/失败/兜底四路径）——GOV-3 已落地；存量修复前后 golden 双锚——GOV-4 已落地（§5.5）。
- **待确认**（GOV-4 回填，定档记录 2026-09-12）：**maxBlockChars=8000 维持**。依据 = 首批蒸馏产出人工复核：32 片（6000 码点窗口）片级要点合并终蒸馏，实际产出 8,637 码点（**口径注记（N4）：8,637 为含 META 头的候选总长，正文 8,365**——apply8.log "validation len=8637" 与 "trim to <=8000" 两行同源），LLM 对「≤8000」指令存在 ~8-10% 超写倾向（同 prompt 两趟分别 8,877 / 8,637，均为含 META 总长口径），8000 定档下经码点安全兜底收尾裁剪可一次到位（7,728），产出人工可读（META 完整、章节结构保留、未闭合事项/演变轨迹在块）；1500 的模板意图与现实信息密度差距过大（169K 存量事实），维持 8000 折中。
  - **启用记录（N1 闭环，2026-09-12）**：GOV-4 复核实证守卫关闭时修复不可持续（修复后 ~10 分钟活跃提取管线复涨 7,728→8,754 且持续增长），生产 yaml `sceneGovernance.enabled: true` 已启用并重启生效——治理守卫进入常态运行，超限块由下一提取批次自动回收。
  - **重放构成注记（N3）**：`2026-09-12T02-42-13-gov4-postrepair-replay.json` 为**方案 A 离线重放**——perQuery 检索结果承继前锚同文件（同日语料快照），仅 layeredMetrics（CC/CTR/SD）按修复后块体重算；experience 漂移缺失实为 **9 条**（非 10 条，承继前锚同款登记）；检索 gate（meanOn 0.06）与 offDeterminism 红牌如实存档，与本次注入形态评估无涉。
