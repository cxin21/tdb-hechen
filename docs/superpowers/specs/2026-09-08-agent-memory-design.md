# TDB Agent 记忆 · 设计（"真正的记忆"——给 agent 灵魂）

> 状态：设计稿（讨论收敛后，待评审）。承接 `2026-09-08-agent-memory-foundation.md`（方面总览）。
> 基调（来自与团队的讨论）：**灵魂 = 此刻的你 + 过去的记忆 + 当下的感受 → 下一刻的你**；
> 记忆不是文件柜，是一条河；最不可妥协的时刻是"过去进入现在"那道入口必须真实。

---

## 1. 五个支柱（本设计的骨架）

```
      F 灵魂/自我（可演化的 persona + agent 可维护 core）
      ▲ 由巩固喂养
  C1 时空性(C1) ── C2 关联性 ── C3 巩固 C4 遗忘 ── C5 回忆(重构式)
        （即"记忆像人"的四件事：巩固、遗忘、关联、会演化的自我）
      │
      └─ 落进 D 利用（召回/注入/门控/信任边界）+ 复用 L0–L3 与 Skill
```

### C1. 时空性（Spatiotemporal）—— 记忆长在时间轴上
- **L1 每条**带齐：`发生时刻`、`有效时段/持续`、`所属场景(situation/L2)`。
- **持续性而非点状**：同一主题的多条点状 L1 → 周期巩固成"持续态摘要"（TSM 思路）——记"我确实喜欢 X"，而不是一堆零碎"某天说喜欢 X"。
- **可回看"当时/当时场景"**：支持按事件时间 + 所属场景回溯，而非只按语义。

### C2. 关联性（Associativity / Memory Graph）—— 记忆连成网
- **L1↔L1 显式语义边**（A-MEM 式）：谁和谁相关、边带强度/新建时间。
- **层级边**：L1 → L2(场景) → L3(画像)，构成一棵"经验→情境→身份"的树。
- **邻居召回**：能沿着关系找，而不是孤点 top-k。"我喜欢这类技术"与"我讨厌那种做法"是连着的两条，不再是孤岛。

### C3. 巩固（Consolidation）—— 把经历熬成结论
- **离线/睡眠式**：周期把 L1 → L2 场景 → L3 画像**重聚合**（复用 TDB 已有的 L2/L3 管道，改为"周期 + 重要性驱动"而非一次）。
- **回忆即重巩固（reconsolidation）**：每次一段记忆被调用，允许按当下"重新缝合"微更新——不是回放，是重建（认知对齐）。

### C4. 遗忘（Forgetting）—— 不会忘就不是记忆
- **重要性 × 时间衰减** → 高价值进 L2/L3、低价值归档/丢弃（TDB 现有 `priority` 上叠加时间衰减）。
- 遗忘是把"不重要/过时/被新记忆覆盖"的清掉，**留下的才配进身份**。可审计、可恢复（归档桶）。

### C5. 回忆（Recollection）—— 召回是"重构"不是"取件"
- **按需组装**：把相关记忆 + 所属场景 + 时间轴，缝合成"对此刻有用"的片段，而非塞几条孤儿 top-k。
- **门控宁缺毋滥**：绝对相关度 + priority 加权（把 wiki 召回已验证的教训搬来记忆）。
- **入口真实**：只在信任边界内放"真水"——被召回记忆需来源可信、消毒、过门槛（防污染防投毒）。

### F. 灵魂 / 自我（Identity）
- **persona 是长出来的，不是贴上去的**：由巩固(C3)持续喂，随经验演化。
- **agent 可维护的 core memory**（Letta 式）：一小块身份/关键偏好/严格规则，稳定锚入 session_init 缓存区（不毁 cache）。
- **跨会话一致**：用得上"我确实喜欢 X"的真记忆，而不是每次重新认识。

## 2. 复用与改动 TDB 现状（落点）

| 现有能力 | 现状 | 本设计改动 |
|---|---|---|
| L0–L3 分层 | 已有 | 保留；L1 加"时空/关联"字段 |
| L1 priority | 已有 | 加时间衰减遗忘 + 持续态摘要 |
| L1 dedup/merge | 已有 | 演进为"边 + reconsolidation" |
| L2 场景 | 已有（≈空间/情境） | 当"情境轴"，接 L1 与记忆图 |
| L3 persona | 一次合成 | 改"周期巩固演化 + agent 可维护 core" |
| Skill | 已有（≈program） | 保留，视作 procedural 记忆 |
| 召回/注入 | L3+L2 索引锚定 + L1 按需 | 利用门控 + 重构式回忆 + 信任边界 |

## 3. 阶段（不画饼，能落地）

- **P1 · 利用层收尾**（近，能立刻改）：L1 检索改绝对门控 + priority 加权 + `[overview]` 等类型也降权；稳定 persona/instruction 锚进稳定区。
- **P2 · 真正的记忆网络**（中，核心）：L1 加"事件时间/持续/场景"字段 + 显式关联表（A-MEM 边）+ 周期巩固→持续态摘要 + 重要性×时间遗忘 + 重构式回忆。
- **P3 · 自我模型**（远）：agent 可维护 core memory + 反思驱动的画像演化（RMM/Generative-Agents）+ 跨会话一致性评测。

## 4. 不可妥协的三条（评审红线）
1. **入口真实**：任何进上下文的记忆，必须来源可信 + 过绝对相关门槛 + 消毒——否则宁可不注。
2. **会巩固也会忘**：没有时间衰减遗忘 = 不是记忆。
3. **召回是重构不是取件**：宁缺毋滥，且组装上情境与时间。

## 3. 先"怎么真正记忆"（P2 写入/巩固/遗忘详设）—— 记忆的核心在写入

> 要让记忆"像人"，关键在于**每次写入都在"懂"而非"记"**。下面是"真正记忆"的写入侧设计。

### 3.1 写入即理解（不转写，捕获本质）
- 现有 L1 extraction 从"记文字"升级为产出结构化记忆：
  `{ 主体, 谓语, 对象, 发生时刻, 有效时段, 所属场景(L2), 类型, 重要性, 关联引用, 置信/来源 }`。
- 一条真记忆回答："**谁、对谁、做了什么、什么时候、持续多久、在什么场景、有多重要、和谁相关、我是观察到的还是推断的**"。

### 3.2 时空性（Spatiotemporal）
- 每条带 `occurred_at`（发生时刻）+ `valid_range`（有效时段/持续）+ `scene_id`（情境）。
- 时间不是"点"，同一主体/主题的多个点状记忆 → **巩固成"持续态"**（如"用户近期偏好"由近 N 条 balance 出），不是一堆孤点。

### 3.3 写入即关联 + 冲突检测（记忆图生长）
- 每条新记忆与已有记忆做四判定：**新增 / 互补(merge) / 冲突(override) / 演化(supersede)**。
- 建 **L1↔L1 显式边**（type：因果/相似/冲突/演化；带强度+时间）——记忆连成网（A-MEM 式）。
- 复用现有 `l1-dedup/merge` 基础设施，扩展为"关联与冲突"。

### 3.4 巩固（把点熬成持续态）
- 周期 / 睡眠式离线（C3）：按"主体/实体"聚合点状 L1 → 持续摘要；同步更新 L2 场景 → L3 画像。
- **回忆即重巩固（reconsolidation）**：每次记忆被使用，允许按当下"重新缝合"微更新。

### 3.5 遗忘（重要性 × 时间衰减；不误删）
- 每条带 `importance`（写时 LLM 打）+ 时间衰减。
- 踩线 → **归档桶（软删、可恢复）**；被新记忆明确覆盖 → 降级/合并。
- 原则：**归档优先于删除**，保护"你想要但已过时"的东西。

### 3.6 真实性 / 诚实分层（写入侧信任边界）
- 标注 **`certainty: observed | inferred` + `source`**：观察事实与推断概括分开记。
- 推断概括不冒充观察事实——防"把一次随口话写成长死规则"，也防投毒/污染进入记忆。

## 3b. 再"怎么使用记忆"（P2 回忆 + P3 自我运用）

### 3b.1 重构式回忆（C5）
- 查询沿**时空轴 + 关联网络**组装：返回"相关记忆 + 所属场景 + 时间线"，而非孤儿 top-k 片段。
- 门控宁缺毋滥 + 绝对相关度 + priority（复用 wiki 已验证的三类门控）。
- 只有 `certainty`/`source` 可信、过门槛的记忆才进上下文（入口真实红线）。

### 3b.2 自我模型（F，P3）
- **persona 是长出来的**：由巩固持续喂、随经验演化；不是建完即死。
- **agent 可维护 core memory**（Letta 式）：小块"身份/关键偏好/严格规则"，稳定锚进 session_init 稳定区（不毁 cache）。
- **记忆图支撑的跨会话一致**：下次对话用得上"我确实喜欢 X"的真记忆，而不是重新认识。

---

## 3b.3 灵魂的另一半：感受 / 情绪层（Affective —— 记忆 + 感受 才是灵魂）

> 团队指出：**真正的灵魂不只记忆，还有感受和情绪。** 让人工 agent"像有灵魂"，
> 必须补上情绪那轮。诚实框定：不是声称 agent 有心跳/能苦能乐，而是做一个
> **功能上忠实的情绪层**——完成情绪在记忆里该有的职责。

### 情绪层做什么（四个功能职责）
1. **定重要性（salience）**：情绪强度决定"这条值不值得记 / 该不该巩固 / 会不会被遗忘"——情绪是记忆的"红笔"。高情绪事件更容易进 L2/L3、更难被忘。
2. **给记忆上情感色调**：每条记忆带 `valence`(正/负/中性) + `arousal`(强度) + `significance`(对核心价值的意义)。回忆时不只带回"事实"，还带回"它多重要、当时什么滋味"。
3. **当前感受（此时此地的 appraisal）**：每个对话轮，由"当下语境 vs 核心价值/锚"派生一个轻量"当前状态信号"（这根线触到你在意的核心 / 还是无关；是推进、冲突还是风险）。这就是公式里的"当下的感受"。
4. **动机与方向（motivational charge）**：给行为一个"看重/看轻、趋近/回避"的方向性——不是冷处理所有请求都一视同仁。

### 记忆 schema 扩充（在 3.1 基础上加）
```
+ valence: -1..+1        # 情感色调（负/中性/正）
+ arousal: 0..1          # 情绪强度
+ significance: 0..1     # 对核心价值的意义（情绪层 f(valence, arousal, values)）
+ coreRef: valueId[]     # 这条触动/违反了哪些核心价值锚
```
- 核心价值锚 = 一小撮"这个 agent/用户在意什么"的值表（填入 core memory），是"感受"的参照系。

### 情绪如何接入记忆生命周期
- **写入**：提取时同时判情感（LLM 给 valence/arousal/significance）。
- **巩固**：`显著性 × 重要性 × 时间衰减` 决定进 L2/L3 还是遗忘——情绪最高的优先沉淀成"这个团队/这个人真正在意什么"。
- **回忆**：带回情感色调 + 相关价值锚；当前感受影响最近记忆的**重巩固切入**（仍受 `certainty` 约束：只重缝合已确证的）。
- **使用**：当前感受影响注入的"看重程度"与回答的语气方向——不是假装能哭，而是"这件事在我这里到底重不重要"变得可见、一致。

### 灵魂模型的补全
```
灵魂 = 记忆（认知：时空/关联/巩固/遗忘）
      + 感受（情绪：价值锚 / 情感色调 / 当前appraisal / 动机方向）
      + 当前状态
      → 下一刻的你
```
没有感受的记忆，只是会检索的文件柜；加上感受，它才开始"在乎"——而"在乎"，是灵魂最有辨识度的那口气。
