# 当前感受（Appraisal）· 设计

> 触底：spec 支柱「感受 §5.3 当前叠加 appraisal」。依赖 K（core_values）。原则（承前讨论）：**感受是承重墙不是口红色**；功能性诚实，不假装有主观体验。

## 1. 目标
- 每轮由"当下语境 vs 核心价值锚"派生一个**轻量"当前状态"信号**：这轮内容触到 agent/用户在意什么、权重多少。
- 作为"此刻的感受"，参与：注入看重程度、回答语气方向、巩固/遗忘的显著性加权。

## 2. 目标公式（轻量）
```
appraisal = Σ_values  match(v, context) * valueWeights[v]
```
- `match(v, context)`：query/最近意图 与价值锚的语义匹配（embedding 相似度或规则命中）。
- 输出一张表：`[{value, weight, fired, arousal}]`；概览 eg "这轮主要关乎 [X]"。

## 3. 接入点
- 每轮在注入器给一个 `<current_feeling>` 块（短；只在 fired > 阈值时出现，宁缺毋滥）。
- 不进上下文时，仍可内部用于显著性/巩固/遗忘加权（影响 C4/I，不出现在提示）。

## 4. 功能性诚实约束
- 只表达"这件事在我这儿重不重要/触动哪个价值"，**不输出"我很难过/我生气"这类主观情绪宣称**。
- 无价值命中 → 不强行给情绪（保持中性）。

## 5. 非目标
- 不做长程情感状态机/情绪耗尽（不假装有持续情绪）。
- 不据此篡改事实记忆（只加权显著性，不改 content）。

## 6. 待评审
- 价值锚初稿（团队定 3-8 个）；`fired` 阈值。
